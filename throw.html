C# throw

Até agora, quem lançava as exceções era o .NET: o int.Parse, a divisão por zero, o array. Nesta aula é a sua vez. Com a palavra throw ("lançar", "atirar"), o seu método avisa que recebeu algo que não dá para aceitar, do mesmo jeito que os métodos do .NET fazem. Você também vai aprender a relançar uma exceção sem perder o rastro dela (throw; × throw ex;), a embrulhar uma exceção em outra e a usar throw no meio de uma expressão.

Você vai aprender
  • Lançar uma exceção com throw new …, e quem a recebe.
  • Qual exceção do .NET escolher: ArgumentException, ArgumentNullException, ArgumentOutOfRangeException, InvalidOperationException, NotImplementedException…
  • Os atalhos de validação: ArgumentNullException.ThrowIfNull, ArgumentOutOfRangeException.ThrowIfNegative e companhia.
  • Relançar dentro de um catch: por que throw; e não throw ex; (o aviso CA2200).
  • Embrulhar uma exceção em outra com InnerException.
  • As expressões throw: ?? throw, no ternário, no switch e depois de =>.
  • Os erros CS0029, CS0156 e CS8115.

Todos os programas rodaram na máquina da Ana, com o .NET 10 (C# 14), usando dotnet run arquivo.cs na pasta ~/cs.

A ideia antes do código

A Ana é a gerente da lojinha, e a funcionária nova está no caixa. Um cliente pede 150% de desconto. A funcionária não deve "dar um jeito" (cobrar um valor negativo, inventar um desconto qualquer): ela deve parar e chamar a gerente, dizendo exatamente o problema: "o desconto pedido é 150%, e o máximo é 100%". Quem sabe o que fazer com isso é a gerente.

O throw é esse "chamar a gerente". Um método que recebe um valor impossível lança uma exceção com uma mensagem clara, e quem chamou o método decide: trata com catch, ou deixa subir.

static class Loja
{

}

Para quem chama, não há diferença entre uma exceção lançada pelo .NET e uma lançada por você: dá para capturar com catch (ArgumentOutOfRangeException e), ler a e.Message etc.

Por que não só mostrar uma mensagem?

O método poderia fazer Console.WriteLine("Desconto inválido") e devolver o preço sem desconto. Mas aí quem chamou nunca fica sabendo que deu errado, e o programa segue com um valor que ninguém pediu. Um método não sabe onde está sendo usado (num programa de console, numa página web, num teste automático) nem o que é melhor fazer em cada caso. O throw entrega o problema a quem sabe.

2. Qual exceção lançar

O .NET já tem exceções prontas para os problemas mais comuns. Prefira sempre uma delas, porque todo programador C# sabe o que cada uma quer dizer:

try
{
    throw new ArgumentException("O nome não pode ficar vazio.");
}
catch (ArgumentException e)
{
    Console.WriteLine(e.Message);
}
try
{
    throw new ArgumentException("O nome não pode ficar vazio.", "nome");
}
catch (ArgumentException e)
{
    Console.WriteLine(e.Message);
    Console.WriteLine(e.ParamName);

{
    throw new InvalidOperationException("O caixa está fechado.");
}
catch (InvalidOperationException e)
{

}

{

}
catch (ArgumentNullException e)

}

3. Os atalhos de validação .NET 6+

Verificar parâmetros no começo dos métodos é tão comum que o .NET ganhou métodos prontos que fazem o if e o throw numa linha só, e ainda descobrem sozinhos o nome do parâmetro:

void Cadastrar(string? nome, int idade, decimal saldo)
{
    ArgumentException.ThrowIfNullOrWhiteSpace(nome);
    ArgumentOutOfRangeException.ThrowIfNegative(idade);
    ArgumentOutOfRangeException.ThrowIfGreaterThan(idade, 130);
    ArgumentOutOfRangeException.ThrowIfNegative(saldo);
    Console.WriteLine($"{nome}, {idade} anos: ok");
}

void Testar(Action acao)
{
    try { acao(); }
    catch (Exception e) { Console.WriteLine($"{e.GetType().Name}: {e.Message}"); }
}

Testar(() => Cadastrar("  ", 29, 10m));
Testar(() => Cadastrar(null, 29, 10m));
Testar(() => Cadastrar("Ana", -1, 10m));
Testar(() => Cadastrar("Ana", 200, 10m));
Testar(() => Cadastrar("Ana", 29, -5m));

4. Relançar: throw; × throw ex;

Às vezes um catch quer fazer alguma coisa com a exceção (registrar num log, por exemplo) e depois deixá-la continuar subindo, porque não sabe resolvê-la. Para isso, dentro do catch, escreva throw; sozinho, sem nada depois:

Estoque.Carregar("doze");

static class Estoque
{
    public static void Carregar(string texto)
    {
        try
        {
            int quantidade = Ler(texto);
            Console.WriteLine($"Quantidade: {quantidade}");
        }
        catch (FormatException)
        {
            Console.WriteLine($"[log] falhou ao ler \"{texto}\"");
            throw;
        }
    }

    static int Ler(string texto)
    {
        return int.Parse(texto);
    }
}

5. Embrulhar: uma exceção dentro da outra

Há uma terceira saída: lançar uma exceção nova, com uma mensagem que faça sentido para quem chamou, guardando a original dentro dela. A original fica na propriedade InnerException ("exceção interna"), e nada se perde:

Estoque.Carregar("doze");

static class Estoque
{
    public static void Carregar(string texto)
    {
        try
        {
            int quantidade = int.Parse(texto);
            Console.WriteLine($"Quantidade: {quantidade}");
        }
        catch (FormatException e)
        {
            throw new InvalidOperationException($"Não deu para carregar o estoque: \"{texto}\".", e);
        }
    }
}

6. Expressões throw C# 7

Até aqui, throw foi uma instrução, numa linha própria. Desde o C# 7 ele também pode aparecer no meio de uma expressão, em quatro lugares: depois de ??, como um dos lados do ternário ? :, num braço de uma expressão switch e depois de =>. Todos de uma vez:

var ana = new Cliente("Ana", 29);
Console.WriteLine($"{ana.Nome}, {ana.Idade} anos");
Console.WriteLine(Categoria(2));
try { var x = new Cliente(null, 30); }
catch (ArgumentNullException e) { Console.WriteLine(e.Message); }
try { var y = new Cliente("Bia", -3); }
catch (ArgumentOutOfRangeException e) { Console.WriteLine(e.Message); }
Console.WriteLine(Categoria(9));

string Categoria(int codigo) => codigo switch
{
    1 => "Alimentos",
    2 => "Limpeza",
    _ => throw new ArgumentOutOfRangeException(nameof(codigo), $"Categoria {codigo} não existe.")
};

class Cliente
{
    public string Nome { get; }
    public int Idade { get; }

    public Cliente(string? nome, int idade)
    {
        Nome = nome ?? throw new ArgumentNullException(nameof(nome));
        Idade = idade >= 0 ? idade : throw new ArgumentOutOfRangeException(nameof(idade), "A idade não pode ser negativa.");
    }

    public decimal CalcularFrete() => throw new NotImplementedException();
}

"Use nome; se for null, lance." O ?? (aula Operadores ??, ?. e ??=) só avalia o lado direito quando o esquerdo é null. É a forma mais comum de expressão throw, e de quebra o compilador entende que Nome nunca fica null.
idade >= 0 ? idade : throw new …
No ternário: "se a idade não é negativa, use-a; senão, lance."
_ => throw new …
No switch (aula Expressões switch): o braço _ ("qualquer outro valor") lança. Sem ele, o compilador avisa (CS8509: "a expressão switch não manipula todos os valores possíveis") e um código desconhecido lança uma SwitchExpressionException genérica (Non-exhaustive switch expression failed to match its input), sem a sua mensagem.
CalcularFrete() => throw new NotImplementedException();

Quando dá errado

CS0029: lançar algo que não é exceção 
throw "deu errado";

$ dotnet run erros.cs
/home/ana/cs/erros.cs(1,7): error CS0029: Não é possível converter implicitamente tipo "string" em "System.Exception"

Ocorreu uma falha no build. Corrija os erros de build e execute novamente.

O que significa: só objetos da família Exception podem ser lançados. Um texto não é uma exceção (em JavaScript e em Python dá para lançar quase qualquer coisa; em C#, não).

Como consertar: embrulhe a mensagem numa exceção: throw new InvalidOperationException("deu errado");.

CS0156: throw; fora de um catch 
Console.WriteLine("oi");
throw;

$ dotnet run erros2.cs
/home/ana/cs/erros2.cs(2,1): error CS0156: Uma instrução throw sem argumentos não é permitida fora de uma cláusula catch

Ocorreu uma falha no build. Corrija os erros de build e execute novamente.

O que significa: throw; quer dizer "relance a exceção que estou tratando". Fora de um catch, não há exceção nenhuma para relançar.

Como consertar: fora do catch, escreva o que lançar: throw new …;.

Aviso CA2200: o rastro some depois de relançar

O que significa: você escreveu throw e; num catch. O rastro da exceção recomeça ali, e a origem do problema some do relatório.

Como consertar: troque por throw;. Se a ideia era lançar uma exceção nova, passe a original como InnerException: throw new …("…", e);.

A exceção "estranha" que o seu método lançou

O que significa: o relatório diz (Parameter 'percentual'), mas o seu método chama o parâmetro de desconto. Alguém renomeou o parâmetro e esqueceu de trocar o texto escrito à mão.

Como consertar: use nameof(desconto) em vez de "desconto": o compilador acompanha a mudança de nome.

Estoque.Carregar("doze");

static class Estoque
{
    public static void Carregar(string texto)
    {
        try
        {
            int quantidade = Ler(texto);
            Console.WriteLine($"Quantidade: {quantidade}");
        }
        catch (FormatException e)
        {
            Console.WriteLine($"[log] falhou ao ler \"{texto}\": {e.Message}");
            throw;
        }
    }

    static int Ler(string texto)
    {
        return int.Parse(texto);
    }
}

Resumo

  • throw new Tipo("mensagem"); lança uma exceção: o método para ali e o problema vai para quem chamou, como as exceções do .NET.
  • Escolha uma exceção pronta: ArgumentNullException, ArgumentOutOfRangeException, ArgumentException para parâmetros; InvalidOperationException para o estado do objeto. Nunca lance Exception.
  • Use nameof(parametro) para o nome do parâmetro. Os atalhos ThrowIfNull, ThrowIfNegative… fazem o if e o throw numa linha.
  • Para relançar num catch, throw;. throw e; apaga a origem do rastro (aviso CA2200).
  • Para trocar por uma exceção mais clara, passe a original: throw new …("…", e), e ela fica em InnerException.
  • Expressões throw: ?? throw, ? … : throw, _ => throw e => throw.
