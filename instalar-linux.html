C# Instalar no Linux

As caixas Experimente do guia compilam e rodam C# no navegador, mas, para programar de verdade, você vai querer o .NET SDK no seu computador. No Linux, isso é fácil: no Ubuntu, ele está no repositório oficial, a um comando de distância. Nesta aula você instala o .NET 10 SDK no Ubuntu (e vê os comandos do Debian, do Fedora e do Arch), confere a instalação com dotnet --version e dotnet --info, vê a mensagem de boas-vindas do primeiro uso e roda o primeiro programa.

Você vai aprender
  • O que é um gerenciador de pacotes e por que ele facilita tudo.
  • Como descobrir se o .NET já está instalado.
  • Como instalar o pacote dotnet-sdk-10.0 no Ubuntu e o que vem junto.
  • Os comandos do Ubuntu 24.04 e 22.04, do Debian, do Fedora, do Arch, do Snap e do script da Microsoft.
  • Como conferir a instalação com dotnet --version e dotnet --info.
  • O que diz a mensagem de boas-vindas que aparece no primeiro uso.
  • Como testar o C# 14 com um programa.

Esta aula é para quem usa Linux. No Windows ou no macOS, veja Instalar no Windows e macOS. As saídas de terminal foram produzidas na máquina da Ana, que usa Ubuntu 26.04 com o .NET já instalado. Por isso, no ponto em que se instala de verdade, a aula mostra a simulação que o próprio apt faz, e marca como ilustrativo o que não foi rodado.

A ideia: a loja de aplicativos do Linux

No celular, você não procura aplicativos em sites aleatórios: abre a loja, procura pelo nome e toca em "Instalar". A loja baixa o aplicativo, instala, e depois avisa quando há atualização. O Linux tem isso há muito mais tempo que os celulares: é o gerenciador de pacotes. Cada programa vem num pacote, e o gerenciador baixa os pacotes de um repositório oficial da sua distribuição, com tudo de que o programa precisa para funcionar (as dependências).

DistribuiçãoGerenciador de pacotes
Ubuntu, Debian, Linux Mint, Pop!_OSapt
Fedora, Red Hat, Rocky Linux, AlmaLinuxdnf
Arch, Manjaro, EndeavourOSpacman
Várias (pacotes que funcionam em qualquer distribuição)snap

Para programar em C#, você precisa de um pacote só: o .NET SDK (aula .NET: SDK, Runtime e CLR). Ele traz o compilador de C#, o Runtime que roda os programas, a biblioteca de classes e o comando dotnet.

1. O .NET já está instalado?

Antes de instalar, pergunte. Abra o terminal (no Ubuntu: Ctrl+Alt+T) e digite:

$ dotnet --version
10.0.112                                        « está instalado: SDK 10.0.112

Se apareceu um número começando com 10., você já tem o .NET 10 e pode pular para a seção 4. Se o número começa com 8. ou 9., você tem uma versão mais antiga, que sai de suporte em novembro de 2026 (aula Versões): instale também o 10, que os dois convivem. Se o .NET não estiver instalado, a resposta é esta:

$ dotnet --version
bash: dotnet: comando não encontrado            « o terminal não achou nenhum programa chamado dotnet
$ echo $?
127                                             « 127: "comando não encontrado"

(No Ubuntu de computador, logo abaixo pode aparecer uma sugestão de qual pacote tem o comando.) Nesse caso, siga a seção da sua distribuição.

2. Ubuntu: dotnet-sdk-10.0

Desde o Ubuntu 22.04, o .NET está no repositório oficial do Ubuntu: a Canonical (a empresa do Ubuntu) compila o .NET a partir do código-fonte e o mantém atualizado, como qualquer outro programa do sistema. No Ubuntu 26.04, o pacote se chama dotnet-sdk-10.0. São dois comandos: o primeiro atualiza a lista de pacotes (o "catálogo da loja"); o segundo instala:

sudo apt update
sudo apt install dotnet-sdk-10.0
sudo
"Faça como administrador" (superuser do). Instalar programas mexe no sistema todo, então é preciso permissão de administrador. O sudo pede a sua senha, que não aparece enquanto você digita (nem bolinhas): é normal, digite e tecle Enter.
apt
O gerenciador de pacotes do Ubuntu e do Debian.
update
Baixa a lista mais nova de pacotes e versões. Não instala nada.
install
A ação: instalar.
dotnet-sdk-10.0
O nome do pacote: o SDK do .NET 10. O -10.0 no nome deixa várias versões conviverem (dotnet-sdk-8.0, dotnet-sdk-10.0…).

O que vem junto

O apt-cache depends mostra de que o pacote depende:

$ apt-cache depends dotnet-sdk-10.0

Repare que o SDK depende do dotnet-runtime-10.0: é por isso que, instalando o SDK, você ganha o Runtime de graça. As quatro últimas dependências (libc6 e companhia) são bibliotecas básicas do sistema que todo Ubuntu já tem.

Você pediu um pacote, e o apt traria dez. As linhas Inst ("instalar") mostram a ordem: primeiro o dotnet-host-10.0 (o comando dotnet) e o dotnet-hostfxr-10.0 (a peça que escolhe qual versão do .NET usar), depois o Runtime e, no fim, o SDK. As linhas Conf ("configurar") vêm depois de tudo desempacotado. Esse é o trabalho do gerenciador: resolver as dependências por você. Somando o tamanho dos dez pacotes, são cerca de 163 MB para baixar e uns 620 MB de espaço em disco.

Numa instalação de verdade, com sudo e sem o -s, o Resumo mostra também o tamanho do download e o espaço necessário, e vêm a pergunta Continuar? [S/n] (tecle Enter: o S maiúsculo é a resposta padrão), as linhas Obter: do download e as linhas Desempacotando … e Configurando … de cada pacote (ilustrativo: a Ana já tinha o .NET). Em uma conexão comum, leva um ou dois minutos.

Nas outras distribuições, os comandos seguem a documentação oficial de cada uma. Eles não foram executados na máquina da Ana (que é Ubuntu), por isso a tabela é ilustrativa:

Sem administrador: o script dotnet-install.sh

A Microsoft oferece um script que instala o .NET na sua pasta pessoal, sem sudo. Ele serve para computadores em que você não é administrador ou para ter uma versão que a sua distribuição ainda não tem (ilustrativo):

wget https://dot.net/v1/dotnet-install.sh -O dotnet-install.sh
chmod +x dotnet-install.sh
./dotnet-install.sh --channel 10.0

O .NET vai para ~/.dotnet, e você precisa avisar o terminal onde ele está, acrescentando ao fim do arquivo ~/.bashrc as linhas export DOTNET_ROOT=$HOME/.dotnet e export PATH=$PATH:$DOTNET_ROOT. A desvantagem: o apt upgrade não atualiza essa cópia; você precisa rodar o script de novo a cada correção.

Qual escolher?

FormaQuando usar

Repositório da MicrosoftNo Debian, ou quando a sua distribuição não tem o .NET 10.
SnapDistribuições sem pacote do .NET, mas com snap.

Não misture duas fontes para a mesma versão

No Ubuntu, instalar o dotnet-sdk-10.0 do Ubuntu e o do repositório da Microsoft causa conflitos: os pacotes têm o mesmo nome, mas os arquivos vão para pastas diferentes (/usr/lib/dotnet e /usr/share/dotnet), e o dotnet pode deixar de achar o SDK. Escolha uma fonte só. No Ubuntu, a recomendação da Microsoft é usar a do próprio Ubuntu.

E a telemetria?

O .NET baixado do site da Microsoft (pelo script, pelo instalador do Windows ou pelo repositório da Microsoft) mostra, nessa mesma mensagem, um parágrafo sobre telemetria: as ferramentas mandam à Microsoft dados anônimos de uso, e você pode desligar isso pondo export DOTNET_CLI_TELEMETRY_OPTOUT=1 no seu ~/.bashrc. O .NET compilado pelo Ubuntu não mostra esse parágrafo, como você viu na saída da Ana.

6. O teste final: o C# 14

O Olá, mundo! provou que o SDK funciona. Falta conferir a versão da linguagem. Este programa usa uma novidade do C# 14, a atribuição com ?. ("se o cliente existir, mude o nome dele"). Não precisa entender o código agora: a aula Operadores ??, ?. e ??= explica.

Cliente? cliente = new Cliente();
cliente?.Nome = "Ana";
Console.WriteLine($"C# 14 funcionando! Cliente: {cliente?.Nome}");

class Cliente
{
    public string Nome { get; set; } = "";
}

$ dotnet run teste14.cs
C# 14 funcionando! Cliente: Ana                   « tudo certo

Se apareceu essa linha, o seu computador está pronto para o guia inteiro. Com um SDK mais antigo (do .NET 9, por exemplo), o mesmo arquivo dá o erro CS9260: O recurso "atribuição condicional nula" não está disponível no C# 13.0 (aula Versões). O mesmo programa roda aqui no editor, que também usa o C# 14:

Atualizando

O gerenciador de pacotes também cuida das atualizações. De tempos em tempos, rode (ilustrativo):

sudo apt update
sudo apt upgrade

O upgrade atualiza todos os programas instalados, incluindo o .NET, para a última correção (de 10.0.112 para 10.0.113, por exemplo). Ele não troca o .NET 10 pelo 11: versões novas do .NET chegam como pacotes novos, com outro número no nome (dotnet-sdk-11.0), e as duas convivem.

Quando dá errado

dotnet: comando não encontrado 
$ dotnet --version
bash: dotnet: comando não encontrado

O que aconteceu: o .NET não está instalado, ou foi instalado pelo script dotnet-install.sh numa pasta que o terminal não conhece.

Como consertar: instale com sudo apt install dotnet-sdk-10.0 (ou o comando da sua distribuição, na seção 3). Se usou o script, confira se as linhas export DOTNET_ROOT=… e export PATH=… estão no ~/.bashrc e abra um terminal novo.

Esqueceu o sudo: você é root? 
$ apt install dotnet-sdk-dbg-10.0
Erro: Não foi possível abrir arquivo de trava /var/lib/dpkg/lock-frontend - open (13: Permissão negada)
Erro: Não é possível adquirir a trava da interface do dpkg (/var/lib/dpkg/lock-frontend), você é root?
$ echo $?
100

O que aconteceu: instalar programas mexe no sistema todo, e só o administrador (o root) pode fazer isso. A "trava" (lock) é um arquivo que garante que só um programa instale pacotes por vez; um usuário comum não tem permissão nem de abri-lo.

Como consertar: repita o comando com sudo na frente. Um atalho do terminal: sudo !! repete o último comando com sudo.

Instalou só o Runtime: No .NET SDKs were found.

O que aconteceu: alguém instalou o dotnet-runtime-10.0 em vez do dotnet-sdk-10.0. O comando dotnet existe e roda programas prontos, mas o dotnet run responde, em inglês, No .NET SDKs were found. A aula .NET: SDK, Runtime e CLR mostra a mensagem inteira.

Como consertar: sudo apt install dotnet-sdk-10.0. O Runtime que já está lá é aproveitado.

Duas fontes misturadas: A fatal error occurred. The folder [/usr/share/dotnet/host/fxr] does not exist (ilustrativo)

O que aconteceu: o .NET foi instalado pelo repositório da Microsoft e pelo do Ubuntu, e o comando dotnet de uma fonte procura as peças na pasta da outra. É o problema do aviso da seção 3. (A tela segue a mensagem descrita na documentação da Microsoft; a máquina da Ana tem uma fonte só.)

Como consertar: remova os pacotes do .NET (sudo apt remove 'dotnet*' 'aspnet*' 'netstandard*', como manda a documentação da Microsoft), tire o repositório que você não quer usar e instale de novo de uma fonte só.

A mensagem de boas-vindas aparece toda vez

O que aconteceu: o .NET não consegue gravar os arquivos "sentinela" em ~/.dotnet, quase sempre porque essa pasta foi criada pelo root (alguém rodou sudo dotnet … uma vez).

Como consertar: devolva a pasta para você com sudo chown -R $USER: ~/.dotnet, e nunca rode o dotnet com sudo: ele não precisa.

Resumo

  • O Linux instala programas pelo gerenciador de pacotes: apt (Ubuntu/Debian), dnf (Fedora), pacman (Arch), snap.
  • Antes de instalar, pergunte: dotnet --version. Para o guia, o SDK tem de começar com 10..
  • No Ubuntu 26.04 e 24.04: sudo apt update e sudo apt install dotnet-sdk-10.0. O apt traz dez pacotes, com o Runtime junto (cerca de 163 MB de download).
  • Debian usa o repositório da Microsoft; Fedora, dnf install dotnet-sdk-10.0; Arch, pacman -S dotnet-sdk; sem administrador, o dotnet-install.sh. Não misture duas fontes.
  • Confira com dotnet --version e dotnet --info. No primeiro comando de verdade, aparece a mensagem Bem-vindo(a) ao .NET 10.0., uma vez só.
  • O teste final: um programa com um recurso do C# 14 tem de rodar.
  • Próximo passo: escolher onde escrever o código, em Editores e IDEs.
