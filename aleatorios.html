C# Números Aleatórios (Random)

Jogos jogam dados, sorteios escolhem um ganhador, quizzes embaralham as perguntas. Em todos eles o programa precisa de números que não dá para prever. No C#, quem sorteia é a classe Random ("aleatório"), e o jeito mais simples de usá-la é o Random.Shared, um sorteador pronto que todo o programa compartilha. Nesta aula você vai jogar dados, sortear alunos, embaralhar cartas, entender o que é a semente e por que, para senhas, a ferramenta é outra.

Você vai aprender
  • Como sortear um número com Random.Shared.Next, e por que o dado é Next(1, 7) e não Next(1, 6).
  • As outras formas: Next(), Next(max), NextDouble() e NextInt64.
  • Como sortear um elemento de um array, vários com GetItems, e embaralhar com Shuffle.
  • O que é a semente, e quando usar new Random(42).
  • Por que o Random não serve para senhas, e o que usar no lugar.
  • Os erros reais: ArgumentOutOfRangeException e CS1955.

Todos os programas foram rodados com o .NET 10 (dotnet --version = 10.0.112, C# 14) na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/cs, com dotnet run arquivo.cs.

Os números desta aula mudam a cada execução

Esse é o objetivo: se você rodar os exemplos (no seu computador ou no editor do guia), vai ver outros números, e cada Rodar dá um resultado diferente. Os terminais da aula mostram uma execução de verdade, entre milhões possíveis. As missões conferem o que vale em qualquer sorteio (o intervalo, se não há repetição), nunca os números sorteados.

A ideia: o caderno de números

Imagine uma professora com um caderno de milhões de números escritos em sequência, sem nenhum padrão que se perceba. Quando alguém pede "um número aleatório", ela lê o próximo número do caderno.

  • Para quem recebe, os números parecem sorte.
  • Mas, se ela começar sempre da mesma página, a turma de amanhã recebe os mesmos números, na mesma ordem.
  • O número da página em que ela começa se chama semente (em inglês, seed).

O Random funciona assim. Os números não são sorte de verdade: são o resultado de uma conta, feita a partir do número anterior. Por isso se chamam pseudoaleatórios ("falsos aleatórios"). Para jogos e sorteios, isso basta. A boa notícia: o Random.Shared escolhe uma página diferente a cada vez que o programa roda, sem você fazer nada.

Por que o 7, e não o 6?

O segundo número do Next é o limite, que fica de fora. Por isso, para um dado, é Next(1, 7). Parece estranho, mas tem uma vantagem: Next(0, n) dá exatamente os índices de um array de n elementos (de 0 a n − 1), e 7 − 1 = 6 é a quantidade de resultados possíveis. Escrever Next(1, 6) é o erro mais comum desta aula: o 6 nunca sai.

Missão: o programa joga o dado 10 mil vezes e mostra o menor e o maior resultado. Rode e veja: o maior é 5, porque o 6 nunca sai. Conserte o Next para o dado dar de 1 a 6 (a saída tem de ter Menor: 1 e Maior: 6).

Menor: 1
Maior: 6
int menor = 100, maior = 0;
for (int i = 0; i < 10_000; i++)
{
    int dado = Random.Shared.Next(1, 6);   // conserte: tem de dar de 1 a 6
    menor = Math.Min(menor, dado);
    maior = Math.Max(maior, dado);
}
Console.WriteLine($"Menor: {menor}");
Console.WriteLine($"Maior: {maior}");

3. Sortear e embaralhar listas

Sortear um elemento

A professora Ana quer sortear quem apresenta o trabalho. O truque é sortear um índice: Next(alunos.Length) dá de 0 até Length − 1, exatamente as posições do array (aula Arrays).

string[] alunos = ["Ana", "Bia", "Caio", "Davi", "Eva"];
string escolhido = alunos[Random.Shared.Next(alunos.Length)];
Console.WriteLine($"Quem apresenta hoje: {escolhido}");
string[] dois = Random.Shared.GetItems(alunos, 2);
Console.WriteLine($"Com repetição: {string.Join(", ", dois)}");

$ dotnet run embaralhar.cs

O Shuffle ("embaralhar") .NET 8 troca os elementos de lugar no próprio array, como o Array.Sort da aula A Classe Array, e com a mesma pegadinha: a ordem antiga some. Todas as cartas continuam lá, cada uma uma vez só. Por isso, para sortear vários sem repetição (os números de uma loteria, a ordem das apresentações), o jeito é embaralhar e pegar os primeiros: cartas[..3].

4. A semente: new Random(42)

Às vezes você quer os mesmos números toda vez: para testar um jogo (e reproduzir o bug que só aparece quando sai 6, 6, 1), ou para gerar sempre o mesmo mapa a partir de um "código do mundo". Para isso, crie o seu próprio sorteador com uma semente fixa:

Random sorteio = new Random(42);
for (int i = 0; i < 10; i++)
{
    Console.Write($"{sorteio.Next(1, 7)} ");
}
Console.WriteLine();
Console.WriteLine(sorteio.Next());
Console.WriteLine(sorteio.NextDouble());
Console.WriteLine(sorteio.Next(100));

Mesmo assim, as missões não dependem deles, porque a documentação do .NET avisa que a conta por trás do Random pode mudar numa versão futura. Use a semente para testar e repetir, não como uma promessa eterna.

E o new Random() dentro do laço?

Você vai ler em tutoriais antigos que criar um new Random() a cada volta do laço repete o mesmo número. Isso acontecia no .NET Framework, que usava o relógio como semente. No .NET moderno, cada new Random() começa num ponto diferente, e o problema sumiu. Mas um new Random(42) dentro do laço repete, sim: cada volta recomeça da página 42.

$ cat laco-new.cs
for (int i = 0; i < 5; i++)
{
    Random r = new Random();
    Console.Write($"{r.Next(1, 7)} ");
}
Console.WriteLine();
for (int i = 0; i < 5; i++)
{
    Random r = new Random(42);
    Console.Write($"{r.Next(1, 7)} ");
}
Console.WriteLine();
$ dotnet run laco-new.cs
2 1 1 6 3
5 5 5 5 5         « semente fixa recriada a cada volta: sempre o primeiro número

A regra simples: um sorteador só, criado uma vez, fora do laço. Com o Random.Shared, nem precisa pensar nisso.

5. Para senhas: RandomNumberGenerator

A sequência do Random sai de uma conta. Para um jogo, ninguém consegue (nem quer) adivinhar o próximo número. Mas, para uma senha, um código de verificação ou um sorteio com dinheiro envolvido, alguém pode querer, e há técnicas para isso. Nesses casos, o .NET tem o RandomNumberGenerator ("gerador de números aleatórios"), que usa o sorteador criptográfico do sistema operacional, feito para ser imprevisível:

using System.Security.Cryptography;
string letras = "abcdefghijkmnpqrstuvwxyz23456789";
char[] senha = new char[10];
for (int i = 0; i < senha.Length; i++)
{
    senha[i] = letras[RandomNumberGenerator.GetInt32(letras.Length)];
}
Console.WriteLine(new string(senha));
Console.WriteLine(RandomNumberGenerator.GetString(letras, 10));

$ dotnet run senha.cs
4vyzbhnuxc
ufypp5sa3m
using System.Security.Cryptography;
"Segurança, criptografia": onde mora o RandomNumberGenerator. Vai na primeira linha do arquivo (aula Namespaces e using).
letras
As letras e algarismos que podem sair. Faltam o l, o o, o 0 e o 1 de propósito: são fáceis de confundir quando alguém copia a senha.
RandomNumberGenerator.GetInt32(letras.Length)
Como o Next(max): de 0 até Length − 1, só que imprevisível. Não tem semente: não dá para repetir.
RandomNumberGenerator.GetString(letras, 10)
O laço inteiro numa linha: 10 caracteres sorteados do texto letras. .NET 8
Regra do guia

Random (e Random.Shared) para jogos e sorteios do dia a dia. RandomNumberGenerator para tudo o que protege alguma coisa: senhas, tokens, códigos de confirmação.

Quando dá errado

O 6 nunca sai: Next(1, 6)

O que significa: o segundo número do Next fica de fora. Next(1, 6) dá de 1 a 5. Não há erro nem aviso: o dado só é "viciado".

Como consertar: o limite é o maior valor mais 1: Next(1, 7). Para um índice de array, Next(v.Length).

Unhandled exception. System.ArgumentOutOfRangeException: 'minValue' cannot be greater than maxValue. 
$ cat invertido.cs
int n = Random.Shared.Next(6, 1);
$ dotnet run invertido.cs
Unhandled exception. System.ArgumentOutOfRangeException: 'minValue' cannot be greater than maxValue. (Parameter 'minValue')
   at System.Random.ThrowMinMaxValueSwapped()
   at System.Random.ThreadSafeRandom.Next(Int32 minValue, Int32 maxValue)
   at Program.<Main>$(String[] args) in /home/ana/cs/invertido.cs:line 1

O que significa: "o mínimo não pode ser maior que o máximo". Os dois números estão trocados. O programa terminou com o código 134. O mesmo acontece com Next(-5) (limite negativo), e o Next(0) não dá erro mas devolve sempre 0, e um alunos[Random.Shared.Next(alunos.Length)] com o array vazio quebra com IndexOutOfRangeException, porque não há ninguém para sortear.

Como consertar: primeiro o menor, depois o maior: Next(1, 6). Se os valores vêm de fora, confira antes, ou use Math.Min e Math.Max (aula Matemática).

error CS1955: O membro não invocável "Random.Shared" não pode ser usado como um método. 
$ cat shared-semente.cs
Random r = Random.Shared(42);
$ dotnet run shared-semente.cs
/home/ana/cs/shared-semente.cs(1,19): error CS1955: O membro não invocável "Random.Shared" não pode ser usado como um método.

Ocorreu uma falha no build. Corrija os erros de build e execute novamente.

O que significa: o Random.Shared é um sorteador pronto, não uma "tecla" que se aperta com parênteses. E ele não aceita semente: a dele é escolhida pelo .NET. Em inglês: Non-invocable member 'Random.Shared' cannot be used like a method.

Como consertar: para uma semente fixa, crie o seu: Random r = new Random(42);. Sem semente, use Random.Shared sem parênteses.

Sempre o mesmo número

O que significa: há uma semente fixa (new Random(42)) que você esqueceu lá, ou ela está sendo criada de novo a cada volta do laço.

Como consertar: use Random.Shared, ou crie o sorteador uma vez, antes do laço.

Missão final: o jogo da loteria

Missão: faça um jogo de loteria: 6 números diferentes, de 1 a 60. As duas últimas linhas do programa conferem o seu jogo; não mude essas linhas. Dica: sortear 6 vezes com Next pode repetir um número. Encha um array com os números de 1 a 60, embaralhe com Shuffle e pegue os 6 primeiros ([..6]). Os números do seu jogo serão outros a cada Rodar; as duas conferências têm de dar True.

Jogo: 4 17 23 38 51 60
6 números diferentes: True
Todos entre 1 e 60: True
int[] jogo = new int[6];

// sorteie aqui os 6 números

Array.Sort(jogo);
Console.WriteLine($"Jogo: {string.Join(" ", jogo)}");
Console.WriteLine($"6 números diferentes: {jogo.Distinct().Count() == 6}");
Console.WriteLine($"Todos entre 1 e 60: {Array.TrueForAll(jogo, n => n >= 1 && n <= 60)}");

int[] numeros = new int[60];
for (int i = 0; i < numeros.Length; i++)
{
    numeros[i] = i + 1;
}
Random.Shared.Shuffle(numeros);
int[] jogo = numeros[..6];

Array.Sort(jogo);
Console.WriteLine($"Jogo: {string.Join(" ", jogo)}");
Console.WriteLine($"6 números diferentes: {jogo.Distinct().Count() == 6}");
Console.WriteLine($"Todos entre 1 e 60: {Array.TrueForAll(jogo, n => n >= 1 && n <= 60)}");

O laço enche o array com 1, 2, 3… 60. O Shuffle embaralha, e a fatia [..6] (aula Índices e Intervalos) pega os 6 primeiros. Como cada número estava no array uma vez só, não tem como repetir. O Array.Sort só deixa o jogo mais fácil de ler, e as duas conferências usam o Distinct do LINQ (que tira os repetidos) e o TrueForAll da aula A Classe Array.

Resumo

  • Os números do Random são pseudoaleatórios: saem de uma conta, a partir de uma semente. Para jogos e sorteios, bastam.
  • Use Random.Shared: um sorteador pronto, com uma semente diferente a cada execução.
  • Next(min, max) sorteia de min até max − 1: um dado é Next(1, 7). Next(v.Length) sorteia um índice do array.
  • NextDouble() dá de 0 a 1; GetItems sorteia vários (com repetição); Shuffle embaralha (e, pegando os primeiros, sorteia sem repetição).
  • new Random(42) repete sempre a mesma sequência: bom para testes. No editor e no dotnet do Linux, a sequência deu igual. Crie o sorteador uma vez, fora do laço.
  • Para senhas e códigos de segurança, RandomNumberGenerator, nunca Random.
