C# Escapes e Strings Literais

Uma string começa e termina com aspas. E se o texto tiver aspas dentro, como Ela disse: "Oi!"? E se precisar de uma quebra de linha, de uma tabulação, ou de um caminho do Windows cheio de barras, como C:\Users\ana? Para isso o C# tem as sequências de escape (\", \n, \\…) e dois tipos especiais de string: a string literal @"…" e a string bruta """…""". Nesta aula você vai ver os três e saber qual escolher em cada caso.

Você vai aprender
  • Por que "Ela disse: "Oi!"" não compila e como resolver com \".
  • As sequências de escape: \n (nova linha), \t (tabulação), \\, \', \u00e9 e o novo \e C# 13.
  • A armadilha do caminho "C:\novo\tabela.txt".
  • Strings literais @"…": barras sem escape e texto em várias linhas.
  • Strings brutas """…""" C# 11: textos com aspas, JSON e interpolação com $$""", e os erros reais.

Todos os programas desta aula foram rodados com o .NET 10 na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/cs, com dotnet run arquivo.cs.

A ideia: um sinal de "atenção, o próximo é especial"

Imagine que você está ditando um recado por telefone e precisa dizer "abre aspas". Se você só falar a palavra "aspas", a pessoa pode escrever a palavra em vez do símbolo. Então vocês combinam um sinal: quando você disser "símbolo: aspas", ela escreve ".

Em C#, esse sinal é a barra invertida \. Dentro de uma string, ela avisa: "o próximo caractere não é o que parece". \" quer dizer "uma aspa de verdade, não o fim do texto"; \n quer dizer "uma quebra de linha". Dizemos que a barra "escapa" o caractere seguinte do seu significado normal, e daí o nome sequência de escape.

Console.WriteLine("Ela disse: "Oi!"");

/home/ana/cs/problema.cs(1,35): error CS1003: Erro de sintaxe, "," esperado

O C# lê a string "Ela disse: " e acha que ela acabou na segunda aspa. Depois encontra Oi! solto, fora de qualquer string, e outra string vazia "". A mensagem ", esperado" é o compilador tentando adivinhar: "se são vários valores, cadê a vírgula entre eles?". O conserto é avisar que aquelas aspas do meio são parte do texto.

2. As sequências de escape

Console.WriteLine("Ela disse: \"Oi!\"");
Console.WriteLine("Linha 1\nLinha 2");
Console.WriteLine("Nome\tIdade");
Console.WriteLine("Ana\t29");
Console.WriteLine("C:\\Users\\ana\\notas.txt");
Console.WriteLine('\'');
Console.WriteLine("Caf\u00e9 \u2764");

$ dotnet run escapes.cs
Ela disse: "Oi!"          « \" virou uma aspa
Linha 1                   « \n quebrou a linha
Linha 2
Nome	Idade                « \t pulou para a próxima coluna de tabulação
Ana	29
C:\Users\ana\notas.txt    « cada \\ virou uma barra só
'                         « \' é uma aspa simples num char
Café ❤                    « \u seguido do código Unicode
\"
Uma aspa dupla dentro da string, sem terminá-la.
\n
New line, "nova linha". O texto continua na linha de baixo. Um WriteLine("a\nb") mostra duas linhas.
\t
Tab, a tabulação. O terminal pula para a próxima "parada" (em geral, de 8 em 8 colunas). Bom para colunas simples; para alinhar de verdade, use {valor,10} (aula Formatar Números).
\\
Uma barra invertida de verdade. Como a barra é o sinal de escape, para escrever uma você precisa de duas.
'\''
Num char (aspas simples), a aspa simples também precisa de escape. Numa string, "'" não precisa.
\u00e9
Um caractere pelo seu código Unicode, em hexadecimal, com 4 dígitos: 00e9 é o é, 2764 é o coração. Útil para caracteres que você não tem no teclado.

Cada sequência de escape ocupa dois caracteres no código, mas é um caractere só no texto: "a\tb\n".Length é 4 (a, tabulação, b, quebra de linha), e "\\".Length é 1.

O \e e as cores do terminal C# 13

Os terminais entendem comandos que começam com o caractere de código 27, chamado ESC. Até o C# 12, escrevia-se \u001b; desde o C# 13 há o atalho \e:

Console.WriteLine("\e[1mnegrito\e[0m normal");
Console.WriteLine((int)'\e');

$ dotnet run esc.cs
negrito normal    « \e[1m liga o negrito; \e[0m volta ao normal
27

Num terminal de verdade, a palavra aparece em negrito e os comandos ficam invisíveis. Isso é um detalhe do terminal, não do C#: se a saída for para um arquivo, os códigos aparecem lá como caracteres estranhos.

Experimente: mude o recado, acrescente mais \n e \t, e tente mostrar o caminho D:\fotos\2026.

Console.WriteLine("Recado da Ana:\n\t\"Volto às 14h.\"\n\t— Ana");
Console.WriteLine("Arquivo: C:\\Users\\ana\\recado.txt");

3. A armadilha do caminho do Windows

Caminhos do Windows usam a barra invertida, e aí mora um perigo: o C# lê as barras como escapes.

Console.WriteLine("C:\novo\tabela.txt");

$ dotnet run caminho.cs
C:
ovo	abela.txt

O \n de \novo virou uma quebra de linha, e o \t de \tabela virou uma tabulação. O pior: não há erro nem aviso, porque \n e \t são escapes válidos. Se a barra vier antes de uma letra que não forma escape, aí sim o compilador reclama (CS1009, em Quando dá errado).

Há dois consertos: dobrar todas as barras ("C:\\novo\\tabela.txt") ou, bem mais legível, usar uma string literal.

E no Linux?

Caminhos do Linux, como /home/ana/cs/notas.txt, usam a barra normal /, que não é escape. Para montar caminhos que funcionem nos dois sistemas, use Path.Combine (aula Pastas e Caminhos).

4. String literal: @"…"

Com um @ antes das aspas, a string vira uma string literal (em inglês, verbatim string, "palavra por palavra"): a barra invertida perde o poder de escape, e o texto é lido exatamente como está.

string caminho = @"C:\pasta\novo\tabela.txt";
Console.WriteLine(caminho);
Console.WriteLine(@"Ela disse: ""Oi!""");
string poema = @"Batatinha quando nasce
espalha a rama pelo chão";
Console.WriteLine(poema);
Console.WriteLine(@"\n não é quebra aqui");

$ dotnet run verbatim.cs
C:\pasta\novo\tabela.txt     « as barras ficaram como estão
Ela disse: "Oi!"             « numa string @, aspas se escrevem dobradas: ""
Batatinha quando nasce       « a quebra de linha do código entrou no texto
espalha a rama pelo chão
\n não é quebra aqui
@"C:\pasta\novo"
Nenhum escape funciona: \n é uma barra e um n. Perfeito para caminhos do Windows e para expressões regulares (aula Regex).
""
Como a barra não escapa mais nada, a única forma de pôr uma aspa dentro de uma string @ é dobrá-la: "" vira ".
várias linhas
A string @ pode atravessar linhas do código, e as quebras entram no texto. Cuidado: os espaços do começo das linhas também entram.

O @ combina com a interpolação: $@"C:\Users\{nome}\Documentos" (ou @$"…", tanto faz a ordem) põe o valor de nome no caminho e mantém as barras.

Missão: o caminho do arquivo da Ana saiu quebrado em duas linhas, com uma tabulação no meio. Conserte a string (com @ ou com barras dobradas) para aparecer C:\novo\tabela.txt.

C:\novo\tabela.txt
string arquivo = "C:\novo\tabela.txt";
Console.WriteLine(arquivo);

string arquivo = @"C:\novo\tabela.txt";
Console.WriteLine(arquivo);

5. String bruta: """…""" C# 11

A string @ resolve as barras, mas as aspas ainda precisam ser dobradas, e os espaços de recuo entram no texto. A string bruta (raw string literal) resolve tudo: ela começa com três aspas (ou mais) e, lá dentro, nada é especial: nem barras, nem aspas.

string json = """
    {
      "nome": "Ana",
      "cidade": "Recife"
    }
    """;
Console.WriteLine(json);
Console.WriteLine("""Ela disse: "Oi!" e saiu.""");

$ dotnet run raw.cs
{                            « o recuo de 4 espaços sumiu
  "nome": "Ana",             « os 2 espaços extras ficaram
  "cidade": "Recife"
}
Ela disse: "Oi!" e saiu.     « aspas sem escape nenhum
""" e uma quebra de linha
Numa string bruta de várias linhas, as três aspas de abertura ficam sozinhas no fim da linha, e o texto começa na linha de baixo.
o recuo
As três aspas de fechamento marcam a margem. Os espaços que estão antes delas (aqui, 4) são retirados de todas as linhas. Por isso o JSON saiu sem recuo, mas com os 2 espaços a mais das linhas de dentro. Assim, o texto pode ficar recuado junto com o código, sem que esse recuo vá para a tela.
a primeira e a última quebra
A quebra logo depois das aspas de abertura e a quebra antes das de fechamento não entram no texto.
"""Ela disse: "Oi!" e saiu."""
Também existe a forma de uma linha só: as três aspas, o texto e as três aspas.

Se o texto tiver três aspas seguidas, abra e feche com quatro (""""), e assim por diante: a string só termina com a mesma quantidade de aspas com que começou.

String bruta com interpolação: $""" e $$"""

Com $ na frente, a string bruta ganha lacunas, como na aula Interpolação. Num JSON, porém, as chaves fazem parte do texto. A solução é usar dois cifrões: aí as lacunas passam a ser {{ }}, e uma chave sozinha é só uma chave.

string nome = "Ana";
int idade = 29;
string json = $$"""
    {
      "nome": "{{nome}}",
      "idade": {{idade}}
    }
    """;
Console.WriteLine(json);
string ola = $"""Olá, "{nome}"!""";
Console.WriteLine(ola);

$ dotnet run rawinterp.cs
{
  "nome": "Ana",
  "idade": 29
}
Olá, "Ana"!
$$"""
A quantidade de $ diz quantas chaves formam uma lacuna. Com $$, {{nome}} é lacuna, e { sozinha aparece no texto.
$"""Olá, "{nome}"!"""
Com um $ só, a lacuna é {nome}, como na interpolação comum, e as aspas continuam livres.

Uma quebra de linha ou uma tabulação apareceu no meio do texto

O que significa: uma barra invertida formou um escape sem você querer, como o \n de C:\novo. Não há erro nem aviso.

Como consertar: use @"…" para textos com barras invertidas.

Resumo

  • A barra invertida \ começa uma sequência de escape: \", \\, \n, \t, \u00e9, \e C# 13. Cada uma é um caractere só.
  • "C:\novo" vira quebra de linha sem aviso. Escape desconhecido (\p) dá CS1009.
  • @"…": string literal. Barras ficam como estão, aspas se dobram (""), pode ter várias linhas.
  • """…""": string bruta C# 11. Nada é especial lá dentro; as aspas de fechamento marcam a margem, e o recuo sai do texto.
  • $"""…{x}…""" interpola; $$"""…{{x}}…""" deixa as chaves simples livres (JSON).
  • String normal sem fechar: CS1010. Bruta com texto na linha das aspas: CS8997. Linha fora da margem: CS8999.
