C# Exceções

Uma exceção é o jeito de o .NET dizer "não consigo continuar": o índice não existe, o texto não é número, o arquivo sumiu. Se ninguém trata, o programa para e mostra a mensagem. Esta página lista as exceções que você mais vai ver, cada uma com o código que a provoca, a mensagem real, o que ela quer dizer e como evitar. Para aprender com calma, veja Exceções, try e catch e throw.

Como usar esta página
  • Copie um pedaço da mensagem que apareceu para você (por exemplo, was not in a correct format) e procure com Ctrl+F.
  • No Linux, as mensagens das exceções saem em inglês, mesmo com o sistema em português (o .NET não traz a tradução delas). As do compilador (CSxxxx) saem em português: estão em Erros do Compilador.
  • Todas foram provocadas de verdade, no dotnet 10.0.112 da máquina da Ana (pasta ~/cs/exc), e conferidas no editor do guia. Onde o editor mostra outra coisa, a tabela diz.

Stack overflow: a que não dá para tratar

static int Contar(int n) => Contar(n + 1) + 1;
Console.WriteLine(Contar(0));

$ dotnet run recursao.cs
Stack overflow.
Repeated 261726 times:
--------------------------------
   at Program.<<Main>$>g__Contar|0_0(Int32)
--------------------------------
   at Program.<Main>$(System.String[])
$ echo $?
134

Uma recursão sem caso de parada enche a pilha de chamadas. O .NET encerra o programa na hora: nenhum catch pega uma StackOverflowException. O Repeated 261726 times é quantas vezes o Contar chegou a se chamar; o número muda um pouco de uma execução para outra (numa segunda vez, deu 261831). O editor do guia mostra a mesma mensagem e o mesmo código 134, mas com uma pilha menor: Repeated 999 times. Como consertar: toda recursão precisa de um caso que para sem chamar de novo.

A família das exceções

Toda exceção é uma classe que herda de Exception. Um catch pega a classe que você escreveu e todas as filhas:

Exception
├── SystemException
│   ├── ArgumentException
│   │   ├── ArgumentNullException
│   │   └── ArgumentOutOfRangeException
│   ├── ArithmeticException
│   │   ├── DivideByZeroException
│   │   └── OverflowException
│   ├── FormatException
│   ├── IndexOutOfRangeException
│   ├── InvalidCastException
│   ├── InvalidOperationException
│   │   └── ObjectDisposedException
│   ├── IO.IOException
│   │   ├── IO.FileNotFoundException
│   │   └── IO.DirectoryNotFoundException
│   ├── Collections.Generic.KeyNotFoundException
│   ├── NotSupportedException
│   ├── NotImplementedException
│   ├── NullReferenceException
│   ├── OperationCanceledException
│   └── UnauthorizedAccessException
└── (as suas: class SaldoInsuficienteException : Exception)

Por isso, num try com vários catch, a mais específica vem primeiro: catch (FileNotFoundException) antes de catch (IOException), e catch (Exception) por último. Ao contrário, o compilador reclama com o erro CS0160 (veja Erros do Compilador). Para criar a sua, aula Exceções Próprias.

O que tem dentro de uma exceção

// propriedades.cs — o que um objeto Exception tem dentro
try
{
    Carregar("config.txt");
}
catch (Exception e)
{
    Console.WriteLine($"Tipo: {e.GetType().Name}");
    Console.WriteLine($"Message: {e.Message}");
    Console.WriteLine($"InnerException: {e.InnerException?.GetType().Name}");
    Console.WriteLine($"InnerException.Message: {e.InnerException?.Message}");
    Console.WriteLine("StackTrace:");
    Console.WriteLine(e.StackTrace);
}

static void Carregar(string arquivo)
{
    try
    {
        File.ReadAllText(arquivo);
    }
    catch (FileNotFoundException e)
    {
        throw new InvalidOperationException($"Não consegui carregar {arquivo}.", e);
    }
}

Tratar: try, catch, when e finally

// trycatch.cs — tratar, filtrar, finally e relançar
foreach (string entrada in new[] { "10", "zero", "0", "99999999999" })
{
    try
    {
        int n = int.Parse(entrada);
        Console.WriteLine($"100 / {n} = {100 / n}");
    }
    catch (FormatException)
    {
        Console.WriteLine($"'{entrada}' não é número.");
    }
    catch (Exception e) when (e is DivideByZeroException or OverflowException)
    {
        Console.WriteLine($"'{entrada}': {e.GetType().Name}");
    }
    finally
    {
        Console.WriteLine("  (fim da tentativa)");
    }
}

Evitar em vez de tratar

Exceção é para o que é excepcional. Para o que acontece sempre (o usuário digita errado, a chave não existe), há métodos que perguntam antes, sem exceção nenhuma:

Em vez de…Que lança…Use…
int.Parse(texto)FormatException, OverflowExceptionint.TryParse(texto, out int n)
d[chave]KeyNotFoundExceptiond.TryGetValue(chave, out var v)
lista.First(…)InvalidOperationExceptionlista.FirstOrDefault(…) e conferir o null
fila.Dequeue()InvalidOperationExceptionfila.TryDequeue(out var x)
(int)objetoInvalidCastExceptionif (objeto is int n)
File.ReadAllText(caminho) sem saber se existeFileNotFoundExceptionif (File.Exists(caminho)) (e ainda um try, porque o arquivo pode sumir entre as duas linhas)
texto.Length com texto anulávelNullReferenceExceptiontexto?.Length ?? 0

Experimente

Missão: a entrada já vem preenchida com vinte, e o programa cai com FormatException (código de saída 134). Troque o int.Parse por int.TryParse para ele mostrar Idade inválida. e terminar normalmente.

Console.Write("Sua idade: ");
string texto = Console.ReadLine() ?? "";
int idade = int.Parse(texto);
Console.WriteLine($"Ano que vem você terá {idade + 1}.");

Console.Write("Sua idade: ");
string texto = Console.ReadLine() ?? "";
if (int.TryParse(texto, out int idade))
{
    Console.WriteLine($"Ano que vem você terá {idade + 1}.");
}
else
{
    Console.WriteLine("Idade inválida.");
}

Resumo

  • Uma exceção não tratada mostra Unhandled exception., o tipo, a mensagem (em inglês) e o rastro, e o programa sai com o código 134.
  • Leia o rastro de cima para baixo até o primeiro arquivo seu: ali está a linha culpada.
  • As campeãs: NullReferenceException, IndexOutOfRangeException/ArgumentOutOfRangeException, FormatException, KeyNotFoundException, InvalidOperationException e FileNotFoundException.
  • Prefira evitar: TryParse, TryGetValue, FirstOrDefault, is, ?..
  • Para tratar: try/catch do mais específico para o mais geral, when para filtrar, finally ou using para liberar recursos, throw; para relançar.
  • Stack overflow não se trata: conserte a recursão.
