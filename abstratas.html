C# Classes Abstratas

Na aula de Polimorfismo, a classe Forma tinha um método Area() que devolvia 0. Era uma gambiarra: "forma" é uma ideia geral, sem área definida. Só um retângulo ou um círculo de verdade têm área. As classes abstratas são o jeito certo de escrever essas ideias gerais: uma classe que serve de modelo para as filhas, que não pode virar objeto sozinha e que pode obrigar as filhas a escrever certos métodos.

Você vai aprender
  • O que é uma classe abstrata (abstract class) e um método abstrato.
  • Por que não dá para criar um objeto de uma classe abstrata (o erro CS0144).
  • Como o compilador obriga as classes filhas a implementar os membros abstratos (CS0534).
  • Propriedades abstratas e o construtor protected.
  • Como misturar membros abstratos e métodos prontos na mesma classe.
  • Quando usar uma classe abstrata e quando usar uma interface.

Todos os programas desta aula rodaram com dotnet run arquivo.cs (veja Rodar com dotnet run) no .NET 10 da máquina da Ana, na pasta ~/cs. As mensagens do compilador estão em português, como no Ubuntu em pt-BR.

A ideia: "instrumento musical"

Numa loja de música, você pode comprar um violão, um piano, uma flauta. Mas não pode comprar "um instrumento musical", genérico. "Instrumento" é uma categoria: diz o que todos têm em comum (todo instrumento toca, tem um nome, tem um preço), mas não existe sozinho. E, embora todo instrumento toque, cada um toca de um jeito: não dá para escrever o "tocar" de um instrumento genérico.

Em C#:

  • A categoria é uma classe abstrata: não se cria objeto dela (new Instrumento() é proibido).
  • O "todo instrumento toca, mas cada um do seu jeito" é um membro abstrato: declarado na classe abstrata, sem corpo, e escrito por cada classe filha com override.

A palavra abstract ("abstrato") vem do latim abstractus, "separado, retirado": algo pensado em geral, separado dos casos concretos. O oposto é concreto: uma classe comum, de que se pode criar objetos.

Uma Forma abstrata

List<Forma> formas = [new Retangulo("Tapete", 2, 3), new Circulo("Mesa", 1)];
foreach (Forma f in formas)
{
    Console.WriteLine(f.Descrever());
}

abstract class Forma
{
    public string Nome { get; }

    protected Forma(string nome)
    {
        Nome = nome;
    }

    public abstract double Area();

    public string Descrever()
    {
        return $"{Nome}: área {Area():F2}";
    }
}

class Retangulo : Forma
{
    public double Largura { get; }
    public double Altura { get; }

    public Retangulo(string nome, double largura, double altura) : base(nome)
    {
        Largura = largura;
        Altura = altura;
    }

    public override double Area()
    {
        return Largura * Altura;
    }
}

class Circulo : Forma
{
    public double Raio { get; }

    public Circulo(string nome, double raio) : base(nome)
    {
        Raio = raio;
    }

    public override double Area()
    {
        return Math.PI * Raio * Raio;
    }
}
abstract class Forma
Uma classe abstrata. Pode ter campos, propriedades, construtores e métodos como qualquer classe, mas não pode ser instanciada com new.
public string Nome { get; }
Uma propriedade comum (veja Propriedades). Toda forma tem nome, e as filhas herdam essa propriedade pronta.
protected Forma(string nome)
Sim, classe abstrata tem construtor! Ele monta a "parte Forma" de cada objeto e é chamado pelas filhas com : base(nome) (veja base). Ele é protected ("protegido"): só as filhas o enxergam. Como ninguém de fora pode fazer new Forma, um construtor public não teria utilidade.
public abstract double Area();
Um método abstrato: só a assinatura, terminada em ;, sem chaves e sem corpo. Ele diz "toda forma tem área", sem dizer como calcular.
public string Descrever()
Um método comum (concreto), pronto, que todas as filhas herdam. Repare que ele usa Area(), mesmo sem saber como ela é calculada. O :F2 mostra 2 casas decimais (veja Formatar Números).
class Retangulo : Forma
O : quer dizer "herda de" (veja Herança).
public override double Area()
Em cada filha, a versão concreta. override = "sobrepor, substituir". Escrever um membro abstrato herdado também se chama implementar o membro. Em C#, o override é obrigatório: sem ele, o compilador não liga o método da filha ao da mãe (você verá o erro mais abaixo).
$ dotnet run formas.cs
Tapete: área 6,00
Mesa: área 3,14      « π × 1 × 1, com 2 casas

Veja como as peças se encaixam: o Descrever() foi escrito uma vez, em Forma. Ao rodar, ele chama Area(), e o polimorfismo escolhe a versão do objeto: a do retângulo para o tapete, a do círculo para a mesa. A classe abstrata escreve o "roteiro"; as filhas preenchem a parte que muda.

Um membro abstrato funciona como um virtual (veja virtual e override) sem versão padrão: o virtual diz "as filhas podem trocar"; o abstract diz "as filhas têm de escrever".

Não dá para instanciar

Uma forma genérica não tem área. Se fosse possível criar uma, o que Descrever() mostraria? O compilador corta o problema pela raiz. A Ana trocou as primeiras linhas do programa por esta:

Este código tem um erro de propósito 
Forma f = new Forma("Coisa");

// … as classes Forma, Retangulo e Circulo de antes

$ dotnet run instancia.cs

Ocorreu uma falha no build. Corrija os erros de build e execute novamente.

O (1,11) é a linha 1, coluna 11: exatamente onde começa o new Forma. Em inglês, a mensagem é Cannot create an instance of the abstract type or interface 'Forma' ("instanciar" = criar uma instância, um objeto). Repare que o problema é só o new. A variável do tipo Forma é permitida, e é muito útil: Forma f = new Circulo("Mesa", 1); funciona, e é assim que o polimorfismo usa as classes abstratas.

A obrigação das filhas

O membro abstrato é uma promessa: "toda forma concreta terá Area()". Por isso, uma filha concreta que esquece de implementá-lo não compila. A Ana apagou o Area() do Circulo:

$ dotnet run semarea.cs
/home/ana/cs/semarea.cs(41,7): error CS0534: "Circulo" não implementa membro abstrato herdado "Forma.Area()"

Ocorreu uma falha no build. Corrija os erros de build e execute novamente.

"Circulo não implementa o membro abstrato herdado Forma.Area()" (em inglês, 'Circulo' does not implement inherited abstract member 'Forma.Area()'). A linha 41 é a do class Circulo : Forma. Há duas saídas:

  1. Implementar o método (o caso normal): escrever public override double Area() no Circulo.
  2. Declarar a filha também abstrata: abstract class Poligono : Forma pode deixar Area() para as filhas dela (Triangulo, Hexagono…). A obrigação só é cobrada da primeira classe concreta da família.

Essa é a grande vantagem sobre a "gambiarra" do return 0 da aula anterior: lá, quem esquecesse de sobrescrever teria uma área zero, em silêncio. Aqui, o programa nem compila.

Esqueceu o override

Um erro muito comum de quem vem do Java ou do Python: escrever o método certo, mas sem a palavra override.

Este código tem um erro de propósito 
class Circulo : Forma
{
    // …
    public double Area()      // falta o override
    {
        return Math.PI * Raio * Raio;
    }
}

$ dotnet run semoverride.cs
/home/ana/cs/semoverride.cs(50,19): warning CS0114: "Circulo.Area()" oculta o membro herdado "Forma.Area()". Para que o membro atual substitua essa implementação, adicione a palavra-chave override. Caso contrário, adicione a palavra-chave new.
/home/ana/cs/semoverride.cs(41,7): error CS0534: "Circulo" não implementa membro abstrato herdado "Forma.Area()"

Ocorreu uma falha no build. Corrija os erros de build e execute novamente.

Duas mensagens. O aviso CS0114 explica o que houve: sem override, o Area() do círculo é um método novo, que só tem o mesmo nome e "esconde" o da mãe. Então o membro abstrato continua sem implementação, e vem o erro CS0534. O conserto está no próprio aviso: "adicione a palavra-chave override".

Propriedades abstratas

Não são só métodos: uma propriedade também pode ser abstrata. Ela declara o get (e, se quiser, o set) sem corpo, e cada filha diz o valor. Assim fica o exemplo dos instrumentos:

Instrumento[] banda = [new Violao(), new Piano()];
foreach (Instrumento i in banda)
{
    i.Tocar();
}

abstract class Instrumento
{
    public abstract string Nome { get; }
    public abstract string Som { get; }

    public void Tocar()
    {
        Console.WriteLine($"O {Nome} faz: {Som}");
    }
}

class Violao : Instrumento
{
    public override string Nome => "violão";
    public override string Som => "plim plim";
}

class Piano : Instrumento
{
    public override string Nome => "piano";
    public override string Som => "plém";
}
public abstract string Nome { get; }
Uma propriedade abstrata só de leitura: "todo instrumento tem um nome", mas a mãe não sabe qual.
public override string Nome => "violão";
A filha implementa a propriedade. O => é a forma curta de um get que só devolve um valor: o mesmo que get { return "violão"; }.
public void Tocar()
O método pronto da mãe, que usa as duas propriedades das filhas.
$ dotnet run instrumentos.cs
O violão faz: plim plim
O piano faz: plém

As regras dos membros abstratos

Membro abstrato não tem corpo

Nem chaves vazias. Um abstract com corpo é uma contradição. A Ana escreveu public abstract double Area() { return 0; }:

$ dotnet run comcorpo.cs
/home/ana/cs/comcorpo.cs(16,28): error CS0500: "Forma.Area()" não pode declarar um corpo porque não está marcado como abstract

Ocorreu uma falha no build. Corrija os erros de build e execute novamente.
Atenção: a tradução está errada

A mensagem em português diz "porque não está marcado como abstract", mas é o contrário! O original em inglês é 'Forma.Area()' cannot declare a body because it is marked abstract: "não pode ter corpo porque está marcado como abstract". O código CS0500 é o que vale. Troque { … } por ;. Se você quer um comportamento padrão que as filhas podem trocar, use virtual no lugar de abstract.

Membro abstrato só em classe abstrata

Se a classe tem um membro abstrato, ela precisa ser abstrata (senão daria para criar um objeto com um método "em branco"). Tirando o abstract da classe Forma:

$ dotnet run naoabstrata.cs
/home/ana/cs/naoabstrata.cs(16,28): error CS0513: 'Forma.Area()' é abstrato, mas está contido no tipo não abstrato 'Forma'

Ocorreu uma falha no build. Corrija os erros de build e execute novamente.

O contrário é permitido: uma classe abstrata sem nenhum membro abstrato. Isso serve para impedir que alguém crie objetos de uma classe que só existe para ser herdada.

Membro abstrato não pode ser private

Uma filha não enxerga o que é private da mãe (veja public, private e internal), então nunca poderia implementá-lo. Com private abstract double Area();, o primeiro erro é:

$ dotnet run privado.cs
/home/ana/cs/privado.cs(16,29): error CS0621: "Forma.Area()": membros virtuais ou abstratos não podem ser privados
…

Use public ou protected (só a família enxerga).

abstract e sealed não combinam

abstract quer dizer "precisa ser herdada"; sealed ("selada") quer dizer "não pode ser herdada" (veja sealed). Juntos, em abstract sealed class Forma:

$ dotnet run selada.cs
/home/ana/cs/selada.cs(7,23): error CS0418: 'Forma': um tipo abstrato não pode ser selado nem estático
/home/ana/cs/selada.cs(11,15): warning CS0628: 'Forma.Forma(string)': novo membro protegido declarado no tipo selado
/home/ana/cs/selada.cs(24,19): error CS0509: "Retangulo": não é possível derivar do tipo sealed "Forma"
/home/ana/cs/selada.cs(35,28): error CS0115: "Retangulo.Area()": não encontrado nenhum método adequado para substituição
/home/ana/cs/selada.cs(41,17): error CS0509: "Circulo": não é possível derivar do tipo sealed "Forma"
/home/ana/cs/selada.cs(50,28): error CS0115: "Circulo.Area()": não encontrado nenhum método adequado para substituição

Ocorreu uma falha no build. Corrija os erros de build e execute novamente.

Um erro só (CS0418, o primeiro) gera vários outros: com a mãe selada, as filhas não podem herdar (CS0509) e os override ficam sem nada para substituir (CS0115). Regra de ouro dos erros: conserte o primeiro e compile de novo. Tirando o sealed, todos somem. A mensagem também cita static: uma classe estática não pode ser abstrata pelo mesmo motivo (ninguém herda dela).

Classe abstrata × interface

A próxima aula apresenta as interfaces, que também declaram membros sem corpo e também não podem ser instanciadas (repare que a mensagem do CS0144 já fala em "tipo abstrato ou interface"). Então, quando usar cada uma? A diferença principal:

  • Uma classe abstrata é uma "mãe incompleta": tem estado (campos e propriedades como Nome), construtores e código pronto para compartilhar. Uma classe só pode herdar de uma.
  • Uma interface é um "contrato de habilidade": diz o que uma classe sabe fazer (IComparable: "sei me comparar"). Não guarda estado de objeto, e uma classe pode implementar várias.
SituaçãoUse
As classes são da mesma família ("é um") e compartilham dados e códigoClasse abstrata (Forma, Funcionario, Conta)
Classes sem parentesco precisam de uma mesma habilidadeInterface (IComparable, IImprimivel, IPagavel)
A classe precisa de mais de um "tipo pai"Interfaces (só há uma classe mãe)
Há um construtor ou campos que todas as filhas precisamClasse abstrata

Muitas vezes as duas aparecem juntas: uma interface diz o que fazer, e uma classe abstrata implementa a parte comum para facilitar a vida das filhas. A comparação completa está em Interfaces.

Quando dá errado

CS0144: "Não é possível criar uma instância do tipo abstrato ou da interface" 
$ dotnet run instancia.cs
/home/ana/cs/instancia.cs(1,11): error CS0144: Não é possível criar uma instância do tipo abstrato ou da interface 'Forma'

O que aconteceu: um new numa classe abstrata.

Como resolver: crie um objeto de uma filha concreta (new Circulo(…)). A variável pode continuar do tipo Forma.

CS0534: "… não implementa membro abstrato herdado …" 
$ dotnet run semarea.cs
/home/ana/cs/semarea.cs(41,7): error CS0534: "Circulo" não implementa membro abstrato herdado "Forma.Area()"

O que aconteceu: uma classe concreta herdou um membro abstrato e não o escreveu. Se o método existe, confira: está com override? A assinatura é idêntica (um Area(int x) não conta)? Se houver um aviso CS0114 logo antes, faltou o override.

Como resolver: implemente o membro com public override …, ou declare a classe como abstract se ela também for uma ideia geral.

CS0500: "… não pode declarar um corpo …" 
$ dotnet run comcorpo.cs
/home/ana/cs/comcorpo.cs(16,28): error CS0500: "Forma.Area()" não pode declarar um corpo porque não está marcado como abstract

O que aconteceu: o método abstrato ganhou chaves (a tradução troca o sentido; o certo é "porque está marcado como abstract").

Como resolver: se ele é abstrato, termine com ;. Se quer um corpo padrão, troque abstract por virtual.

CS0513: "… é abstrato, mas está contido no tipo não abstrato …" 
$ dotnet run naoabstrata.cs
/home/ana/cs/naoabstrata.cs(16,28): error CS0513: 'Forma.Area()' é abstrato, mas está contido no tipo não abstrato 'Forma'

O que aconteceu: um membro abstrato numa classe comum.

Como resolver: escreva abstract class ou dê um corpo ao membro (e troque abstract por virtual).

Resumo

  • abstract class = uma ideia geral, que serve de modelo: tem propriedades, construtores e métodos, mas não pode ser instanciada (CS0144).
  • abstract num método ou propriedade = só a assinatura, terminada em ;. Toda filha concreta é obrigada a implementá-lo com override (CS0534). Sem o override, vem o aviso CS0114 e o mesmo erro.
  • Métodos concretos da classe abstrata podem chamar os abstratos: a mãe escreve o roteiro, as filhas preenchem as partes que mudam.
  • O construtor de uma classe abstrata costuma ser protected; as filhas o chamam com : base(…).
  • Variáveis, listas e parâmetros do tipo abstrato são o normal: Forma f = new Circulo(…).
  • Classe abstrata: família com dados e código em comum (só uma mãe). Interface: habilidade que várias classes, mesmo sem parentesco, podem ter. Próxima aula: Interfaces.
