C# Editores e IDEs

Código C# é texto puro: dá para escrevê-lo até no Bloco de Notas. Mas um bom editor de código faz a diferença entre sofrer e aprender: ele pinta cada parte do código de uma cor, sublinha o erro enquanto você digita, completa os nomes (Console.Wr… vira Console.WriteLine) e roda o programa com um atalho. Nesta aula você conhece os editores e IDEs mais usados para C#, prepara o VS Code e aprende os cuidados com o arquivo que evitam muita dor de cabeça.

Você vai aprender
  • A diferença entre editor de texto, editor de código e IDE, e por que nenhum deles é o compilador.
  • Como preparar o VS Code com as extensões C# e C# Dev Kit, e o que diz a licença de cada uma.
  • Como rodar o programa pelo terminal integrado do VS Code.
  • O que oferecem o Visual Studio 2026, o JetBrains Rider e o Vim/Neovim, e qual escolher.
  • Os cuidados com o arquivo: a extensão .cs, a codificação UTF-8 e salvar antes de rodar.

Esta aula não tem capturas de tela: os menus mudam a cada versão, e o guia descreve o caminho pelo nome dos botões. As saídas de terminal foram produzidas na máquina fictícia da Ana, com o .NET 10, na pasta ~/cs.

Nenhum deles é o compilador

O editor só ajuda a escrever. Quem compila e roda o programa continua sendo o .NET SDK, que você instalou na aula Instalar no Linux ou Instalar no Windows e macOS. Sem o SDK, o mais bonito dos editores não consegue rodar nada. A exceção é o Visual Studio, que instala o SDK junto. Mesmo assim, por baixo, tudo usa o mesmo comando dotnet e o mesmo compilador Roslyn: o erro que o editor sublinha é o mesmo que o dotnet run mostra.

1. Por que um editor de código ajuda tanto

Veja um engano que todo iniciante comete: esquecer de fechar as aspas. A Ana escreveu "Olá, mundo! e o " do fim sumiu:

Console.WriteLine("Olá, mundo!);
Console.WriteLine("Tchau!");

Num editor de código, o problema salta aos olhos antes mesmo de rodar: o texto entre aspas tem uma cor própria, e essa cor "vaza" até o fim da linha. O editor também sublinha o erro com uma ondinha vermelha. Sem essa ajuda, a Ana só descobre ao rodar:

$ dotnet run aspas.cs
/home/ana/cs/aspas.cs(1,19): error CS1010: Newline em constante     « a primeira mensagem diz tudo
/home/ana/cs/aspas.cs(1,33): error CS1003: Erro de sintaxe, "," esperado
/home/ana/cs/aspas.cs(2,28): error CS1026: ) esperado               « a linha 2 está certa!

Ocorreu uma falha no build. Corrija os erros de build e execute novamente.

A primeira mensagem já diz o problema: CS1010: Newline em constante, "quebra de linha dentro de uma constante": o texto começou na coluna 19 (nas aspas) e chegou ao fim da linha sem fechar. As outras são consequência: sem as aspas fechadas, o compilador se perdeu e reclamou até da linha 2, que está certa. Regra de ouro, que a aula Lendo Erros do Compilador detalha: leia e conserte a primeira mensagem, e rode de novo.

O editor do guia também pinta o código. Repare nas cores da linha 1:

Missão: rode e leia o erro. Depois feche as aspas no lugar certo (depois do !, antes do )) e rode de novo: devem aparecer as duas linhas.

Console.WriteLine("Olá, mundo!);
Console.WriteLine("Tchau!");

Console.WriteLine("Olá, mundo!");
Console.WriteLine("Tchau!");

Além das cores, um editor de código:

  • numera as linhas, os mesmos números que as mensagens do compilador citam (aspas.cs(1,19) é a linha 1, coluna 19);
  • faz o recuo sozinho: depois de um {, a próxima linha já começa mais para dentro;
  • fecha os pares: digitou (, ele põe o ); digitou ", ele põe o outro ";
  • completa nomes (o IntelliSense): digite Console. e ele mostra a lista de tudo o que existe dentro do Console, com uma explicação de cada item;
  • marca erros e avisos enquanto você digita, com os mesmos códigos CSxxxx do compilador, e muitas vezes oferece o conserto (a "lâmpada", Ctrl+.).

2. VS Code

O Visual Studio Code (VS Code) é um editor de código gratuito da Microsoft, para Windows, Linux e macOS. Sozinho, ele só pinta o código; com as extensões de C#, vira um ambiente completo. É leve, muito usado e o recomendado para seguir o guia. Não confunda com o Visual Studio (sem "Code"), a IDE pesada só para Windows (seção 3).

Instalando

  1. Baixe em code.visualstudio.com: no Ubuntu e no Debian, o arquivo .deb; no Fedora, o .rpm; no Windows e no macOS, o instalador.
  2. Instale como qualquer programa. No Ubuntu, dê dois cliques no .deb ou rode sudo apt install ./code_*.deb na pasta do download.
  3. Abra a pasta dos seus programas: no terminal, code ~/cs; ou, no VS Code, Arquivo › Abrir Pasta. Trabalhe sempre com a pasta aberta, não com arquivos soltos.
  4. Crie um arquivo com Arquivo › Novo Arquivo e salve com um nome terminado em .cs, como ola.cs. O VS Code reconhece a linguagem (o canto de baixo da janela passa a dizer C#) e oferece instalar a extensão.

As extensões: C# e C# Dev Kit

Abra a aba Extensões (o ícone de quadradinhos na barra da esquerda, ou Ctrl+Shift+X) e procure por C# Dev Kit. Ao instalá-la, o VS Code instala junto a extensão C#, de que ela depende:

Rodando pelo terminal integrado

O VS Code tem um terminal dentro dele: Exibir › Terminal, ou Ctrl+' (a tecla do apóstrofo, no teclado brasileiro). É um terminal normal, já aberto na pasta do projeto: ali você roda o mesmo dotnet run ola.cs do guia.

$ dotnet run ola.cs
Olá, mundo!

Esse é o jeito recomendado para o Nível 1: escreva no editor, salve com Ctrl+S e rode no terminal integrado. Você vê exatamente as mesmas mensagens do guia.

Uma configuração que vale a pena: salvar sozinho

O erro mais bobo do mundo é rodar sem salvar (veja a seção 5). Para evitá-lo, ligue o salvamento automático: Arquivo › Salvamento Automático. A partir daí, o VS Code salva o arquivo sempre que você para de digitar por um instante.

3. Visual Studio 2026 (Windows)

O Visual Studio é a IDE completa da Microsoft para C#, com mais de 25 anos de estrada. Ele só existe para Windows. A versão atual, o Visual Studio 2026 (versão 18), é a primeira com suporte ao .NET 10. A edição Community é gratuita para estudantes, pessoas físicas, projetos de código aberto e pequenas empresas.

  • Prós: tudo pronto e integrado: projetos, depurador visual muito bom, editor de janelas (para WPF e WinForms), testes, análise de desempenho. Instala o .NET SDK junto.
  • Contras: pesado (vários gigabytes) e só Windows. Ele esconde muito do que acontece por baixo, e o guia ensina pelo terminal.

Na instalação, marque a carga de trabalho Desenvolvimento para desktop com .NET. Para os exemplos do guia, crie um projeto do tipo Aplicativo de Console (aula Projetos (dotnet new console)) e escreva o código no Program.cs. O Visual Studio for Mac, que existia antes, foi descontinuado em 31 de agosto de 2024: no Mac, use o VS Code ou o Rider.

4. Outras opções

JetBrains Rider

O Rider é a IDE de C# da JetBrains (a mesma empresa do IntelliJ, para Java). Ele roda no Windows, no Linux e no macOS, tem um analisador de código muito esperto (sugere melhorias em quase toda linha) e um bom depurador. Desde outubro de 2024, ele é gratuito para uso não comercial (estudar, projetos pessoais, código aberto); para trabalho, é pago. Muita gente que programa C# no Linux ou no Mac usa o Rider.

Vim, Neovim, Emacs, Zed, Sublime Text

Editores que entendem o LSP (Language Server Protocol, um jeito padrão de um editor conversar com um "servidor de linguagem") ganham completar e erros sublinhados para C# com um servidor de linguagem baseado no Roslyn. A configuração é manual e cada editor tem a sua. São ótimos para quem já usa um deles; para quem está começando, o VS Code dá menos trabalho.

5. Os cuidados com o arquivo

A extensão .cs

O nome do arquivo tem de terminar em .cs: é por ela que o editor sabe que é C# e que o dotnet run sabe que é um programa. Cuidado com o Windows, que esconde as extensões: o Bloco de Notas pode salvar ola.cs.txt (aula Instalar no Windows e macOS). Use nomes sem espaços e sem acentos (ola.cs, media_notas.cs): funcionam com o dotnet e evitam aspas nos comandos.

A codificação: UTF-8

Um arquivo de texto guarda letras como números, e há mais de uma "tabela" para isso (a codificação). Hoje, o padrão do mundo é o UTF-8, que tem todas as letras de todas as línguas, e é ele que o .NET espera. O VS Code, o Visual Studio e o Rider já salvam em UTF-8. Mas editores antigos do Windows às vezes salvam em Latin-1 (ISO-8859-1), e aí os acentos estragam. A Ana gravou o mesmo Olá, mundo! nas duas codificações para comparar:

$ file ola.cs latin1.cs                           « o file descobre a codificação
ola.cs:    Unicode text, UTF-8 text
latin1.cs: ISO-8859 text                          « ISO-8859 = Latin-1
$ dotnet run ola.cs
Olá, mundo!
$ dotnet run latin1.cs
Ol�, mundo!                                       « o á virou �

O � é o "caractere de substituição": o compilador leu o arquivo como UTF-8, encontrou um byte que não faz sentido em UTF-8 (o á do Latin-1) e o trocou por esse símbolo. O programa compilou e rodou, só que com a letra errada, e o erro passa despercebido. Como evitar: salve sempre em UTF-8. No VS Code, a codificação aparece no canto de baixo da janela (UTF-8); clicando nela, dá para escolher Salvar com Codificação › UTF-8.

Salvar antes de rodar

O dotnet run lê o arquivo que está no disco, não o que está na tela do editor. Se você mudou o código e não salvou, ele roda a versão antiga, e você fica sem entender por que nada mudou. No VS Code, um arquivo não salvo tem um círculo branco no lugar do × da aba. Salve com Ctrl+S (no Mac, Cmd+S), ou ligue o salvamento automático.

Quando dá errado

Mudei o código e a saída não mudou

O que aconteceu: o arquivo não foi salvo. O dotnet run compilou e rodou a versão que estava no disco.

Como consertar: salve (Ctrl+S) e rode de novo. Confira se a aba do arquivo não tem o círculo de "não salvo".

Os acentos saem como � 
$ dotnet run latin1.cs
Ol�, mundo!

O que aconteceu: o arquivo foi salvo numa codificação antiga (Latin-1), e o compilador esperava UTF-8.

Como consertar: abra o arquivo no VS Code, clique na codificação no canto de baixo, escolha Reabrir com Codificação › Western (ISO 8859-1) para ver os acentos certos e depois Salvar com Codificação › UTF-8. No terminal do Linux, o iconv -f latin1 -t utf-8 latin1.cs -o novo.cs faz a conversão.

O VS Code não pinta o código nem completa nada

O que aconteceu: a extensão C# não está instalada, ou o arquivo não termina em .cs (o canto de baixo da janela diz Texto sem Formatação em vez de C#), ou o .NET SDK não está instalado e a extensão não consegue iniciar o servidor de linguagem (ela avisa com uma mensagem no canto da tela).

Como consertar: confira as três coisas, nessa ordem: o nome do arquivo, a extensão C# na aba Extensões e o dotnet --version no terminal integrado. Depois, recarregue a janela (Ctrl+Shift+P e Developer: Reload Window).

O editor sublinha um erro, mas o dotnet run funciona (ou o contrário)

O que aconteceu: o editor analisa o código enquanto você digita e, às vezes, fica um passo atrás (por exemplo, logo depois de você mudar a versão do .NET ou criar um arquivo).

Como consertar: quem manda é o dotnet run. Salve e rode no terminal; se o erro sumiu lá, recarregue a janela do editor.

Missão: a lista da Ana tem três erros de digitação, do tipo que um editor de código sublinha na hora: aspas que não fecham, um ponto e vírgula esquecido e um WriteLine com o l minúsculo. Conserte um por vez, lendo a primeira mensagem a cada vez, até a saída ser a lista com arroz, feijão e café.

Resumo

  • Editor de texto escreve; editor de código pinta, completa e marca erros; IDE junta tudo com projetos e depurador. Nenhum deles é o compilador: quem compila é o .NET SDK.
  • Para começar: VS Code com a extensão C# (código aberto); a C# Dev Kit é opcional, gratuita para uso pessoal e pequenas equipes.
  • Rode pelo terminal integrado (Ctrl+') com dotnet run ola.cs, como no guia.
  • Visual Studio 2026: IDE completa, só Windows, Community gratuita. Rider: Windows, Linux e Mac, grátis para uso não comercial. O Visual Studio for Mac acabou em 2024.
  • Cuidados: arquivo terminado em .cs, salvo em UTF-8 (senão, Ol�), e salvo antes de rodar.
  • Com vários erros, conserte o primeiro e rode de novo.
  • Próximo passo: conhecer o editor do navegador em O Editor do Guia e escrever o primeiro programa em Olá, Mundo.
