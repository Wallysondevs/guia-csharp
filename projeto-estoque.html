Projeto Estoque da Lojinha

A Ana tem uma lojinha de papelaria e controla o estoque num caderno: quantos cadernos, canetas e mochilas ainda tem, e quanto custa cada um. Toda semana ela faz as mesmas perguntas: "o que está acabando?", "quanto vale tudo o que está na prateleira?", "qual categoria dá mais dinheiro?". Neste projeto, ela troca o caderno por um programa em C# que responde a essas perguntas com LINQ, em uma linha cada, e que guarda o estoque num arquivo para não esquecer nada de um dia para o outro.

Você vai praticar
  • Descrever um produto com um record e guardar todos numa List<T>.
  • Mostrar uma tabela alinhada com interpolação e o formato de dinheiro :C (Formatar Números).
  • Fazer perguntas à lista com LINQ: Where, OrderBy, Select, Count, Sum e MaxBy.
  • Agrupar por categoria com GroupBy e procurar com FirstOrDefault.
  • Fazer um menu com Console.ReadLine e int.TryParse, e "mudar" um record com with.
  • Guardar o estoque em estoque.csv sem perder os centavos por causa da cultura pt-BR.

O que vamos construir

O programa pronto, na máquina da Ana. Na primeira vez, ainda não existe o arquivo, e ele começa com os produtos do caderno de papel. Ela vê o que está acabando, recebe 20 borrachas, vende 5 canetas, tenta vender 3 mochilas (só há 2) e sai:

Versão 1 · A ficha do produto e a lista

Pense nas fichas de papel da Ana: cada produto tem uma, com os mesmos campos na mesma ordem (código, nome, categoria, quantidade e preço). Em C#, o desenho da ficha é um record, e a caixa com todas as fichas é uma List<Produto> ("lista de produtos").

A primeira versão não pergunta nada ao usuário. Ela só monta a lista e mostra a tabela do estoque:

LinhaO que faz
record Produto(int Codigo, string Nome, …, decimal Preco);O desenho da ficha, na última linha do arquivo. Esta linha cria o tipo Produto, com cinco propriedades e um construtor que recebe as cinco, na ordem. Em Program.cs, os tipos ficam depois das instruções (aula Program.cs e o Main). C# 9
decimal PrecoDinheiro é sempre decimal: ele guarda 15,90 exato, e o double não (aula float, double e decimal).
List<Produto> estoque = [ … ];Cria a lista já com sete produtos. Os colchetes são uma expressão de coleção C# 12; antes dela, escrevia-se new List<Produto> { … }.
new(1, "Caderno", "Papelaria", 12, 15.90m)Cria um Produto. O C# já sabe o tipo (é uma lista de Produto), por isso basta new(…) C# 9. O m no fim de 15.90m diz "isto é um decimal". No código, o separador decimal é sempre o ponto.
foreach (Produto p in estoque)Passa por cada ficha, da primeira à última. Dentro do laço, p é o produto da vez (aula foreach).
{p.Codigo,3}O número depois da vírgula é a largura: o código ocupa 3 posições, alinhado à direita.
{p.Nome,-10}Largura negativa alinha à esquerda: o nome ocupa 10 posições, e o que sobra vira espaço.
{p.Preco,10:C}Largura 10 e o formato C ("currency", moeda). Na máquina da Ana, em pt-BR, 15.90m sai R$ 15,90.

A ficha não se apaga: records são imutáveis

A Ana vendeu um caderno e tentou diminuir a quantidade como faria numa variável comum:

CS8852: a propriedade só pode ser atribuída na criação 
List<Produto> estoque =
[
    new(1, "Caderno", "Papelaria", 12, 15.90m),
];

estoque[0].Quantidade = 11;     // vendeu um caderno
Console.WriteLine(estoque[0]);

record Produto(int Codigo, string Nome, string Categoria, int Quantidade, decimal Preco);

$ dotnet run
/home/ana/projetos/Estoque/Program.cs(6,1): error CS8852: A propriedade somente de inicialização ou o indexador 'Produto.Quantidade' só pode ser atribuído em um inicializador de objeto, em 'this' ou 'base' em um construtor de instância ou em um acessador 'init'. [/home/ana/projetos/Estoque/Estoque.csproj]

Ocorreu uma falha no build. Corrija os erros de build e execute novamente.

O que significa: as propriedades de um record posicional são init: recebem o valor quando a ficha é criada e depois não mudam mais (aula readonly e init). Em inglês, a mensagem começa com Init-only property or indexer 'Produto.Quantidade' can only be assigned….

Como consertar: em vez de rasurar a ficha, a Ana preenche uma ficha nova, igual à velha, com a quantidade trocada, e põe a nova no lugar. É isso que o with faz:

List<Produto> estoque =
[
    new(1, "Caderno", "Papelaria", 12, 15.90m),
];

estoque[0] = estoque[0] with { Quantidade = 11 };
Console.WriteLine(estoque[0]);

record Produto(int Codigo, string Nome, string Categoria, int Quantidade, decimal Preco);

$ dotnet run
Produto { Codigo = 1, Nome = Caderno, Categoria = Papelaria, Quantidade = 11, Preco = 15,90 }

De quebra, o Console.WriteLine de um record mostra todos os campos, com nome: ótimo para conferir o que está dentro.

Por que não usar uma class com set, que deixaria mudar? Daria certo também. O record foi escolhido porque, com LINQ, a maior parte do trabalho é ler o estoque, e uma ficha que ninguém muda por engano é mais segura. Só a versão 4 vai mudar quantidades, e sempre num lugar só.

Versão 2 · Perguntas ao estoque com LINQ

Com a lista pronta, chegam as perguntas da Ana. Sem LINQ, cada pergunta seria um foreach com um if e uma variável para ir somando. Com LINQ, cada pergunta vira uma frase: "do estoque, onde a quantidade é menor que 5"; "do estoque, a soma de quantidade vezes preço".

// Estoque da Lojinha — versão 2: perguntas com LINQ
List<Produto> estoque =
[
    new(1, "Caderno", "Papelaria", 12, 15.90m),
    new(2, "Caneta", "Escrita", 40, 2.50m),
    new(3, "Borracha", "Escrita", 3, 1.75m),
    new(4, "Mochila", "Bolsas", 2, 89.90m),
    new(5, "Lápis", "Escrita", 60, 1.20m),
    new(6, "Papel A4", "Papelaria", 4, 27.50m),
    new(7, "Estojo", "Bolsas", 6, 19.90m),
];

// 1. Quais produtos estão acabando? (menos de 5 unidades)
var acabando = estoque.Where(p => p.Quantidade < 5);
Console.WriteLine("Comprar logo:");
foreach (Produto p in acabando)
{
    Console.WriteLine($"  {p.Nome} (só {p.Quantidade})");
}

// 2. Os nomes em ordem alfabética
var nomes = estoque.OrderBy(p => p.Nome).Select(p => p.Nome);
Console.WriteLine($"Em ordem: {string.Join(", ", nomes)}");

// 3. Contas sobre o estoque inteiro
int unidades = estoque.Sum(p => p.Quantidade);
decimal valor = estoque.Sum(p => p.Quantidade * p.Preco);
int caros = estoque.Count(p => p.Preco > 10m);
Produto maisCaro = estoque.MaxBy(p => p.Preco)!;

Console.WriteLine($"Unidades: {unidades}");
Console.WriteLine($"Valor do estoque: {valor:C}");
Console.WriteLine($"Produtos acima de R$ 10: {caros}");
Console.WriteLine($"Mais caro: {maisCaro.Nome}, {maisCaro.Preco:C}");

record Produto(int Codigo, string Nome, string Categoria, int Quantidade, decimal Preco);
LinhaO que faz
estoque.Where(p => p.Quantidade < 5)Filtra: fica só com os produtos em que a condição é verdadeira. O p => p.Quantidade < 5 é uma lambda: "dado um produto p, diga se a quantidade dele é menor que 5". Aula: Filtrar e Projetar.
var acabando = …;O resultado é um IEnumerable<Produto>, uma sequência que se percorre com foreach. O var poupa escrever esse nome comprido.
.OrderBy(p => p.Nome)Ordena pelo nome, de A a Z (aula Ordenar). A lista original continua na ordem de antes.
.Select(p => p.Nome)Projeta: troca cada produto por outra coisa, aqui só o nome. O resultado é uma sequência de string.
string.Join(", ", nomes)Junta os textos numa linha só, com ", " entre eles.
estoque.Sum(p => p.Quantidade)Soma o que a lambda devolve para cada produto: todas as unidades.
estoque.Sum(p => p.Quantidade * p.Preco)O valor do estoque: para cada produto, quantidade × preço, e a soma de tudo. int vezes decimal dá decimal, e a conta é exata. Aula: Agregar.
estoque.Count(p => p.Preco > 10m)Conta quantos produtos cumprem a condição. Sem lambda, Count() conta todos.
estoque.MaxBy(p => p.Preco)!Devolve o produto de maior preço (o Max devolveria só o preço). Numa lista vazia, ele devolveria null; o ! diz ao compilador "aqui não está vazia" e evita um aviso (aula Referências Anuláveis). .NET 6

CS1061: a sequência não tem Nome

A Ana quis mostrar o nome do que está acabando direto do resultado do Where:

List<Produto> estoque =
[
    new(3, "Borracha", "Escrita", 3, 1.75m),
    new(4, "Mochila", "Bolsas", 2, 89.90m),
];

var acabando = estoque.Where(p => p.Quantidade < 5);
Console.WriteLine(acabando.Nome);

record Produto(int Codigo, string Nome, string Categoria, int Quantidade, decimal Preco);

$ dotnet run
/home/ana/projetos/Estoque/Program.cs(8,28): error CS1061: ‘IEnumerable<Produto>’ não contém uma definição para "Nome" e não foi possível encontrar nenhum método de extensão "Nome" que aceite um primeiro argumento do tipo ‘IEnumerable<Produto>’ (você está se esquecendo de usar uma diretiva ou uma referência de assembly?) [/home/ana/projetos/Estoque/Estoque.csproj]

Ocorreu uma falha no build. Corrija os erros de build e execute novamente.

O que significa: o Where não devolve um produto, devolve uma sequência de produtos (podem ser zero, um ou vários). Uma sequência não tem nome; cada produto dentro dela, sim. A dica do fim (diretiva ou referência de assembly) não ajuda aqui: ela aparece em todo CS1061.

Como consertar: percorra com foreach, como na versão 2; ou projete os nomes: string.Join(", ", acabando.Select(p => p.Nome)); ou, se quer só o primeiro, acabando.First().Nome.

A consulta é uma receita, não uma foto

Um detalhe do LINQ que surpreende: a linha do Where não separa os produtos naquela hora. Ela guarda a "receita" do filtro, e a receita roda de novo a cada vez que alguém percorre o resultado. Veja o que acontece quando o estoque muda depois da consulta:

List<Produto> estoque =
[
    new(1, "Caderno", "Papelaria", 12, 15.90m),
    new(3, "Borracha", "Escrita", 3, 1.75m),
    new(4, "Mochila", "Bolsas", 2, 89.90m),
];

var acabando = estoque.Where(p => p.Quantidade < 5);
Console.WriteLine($"Acabando: {acabando.Count()}");

estoque[1] = estoque[1] with { Quantidade = 30 };   // chegou uma caixa de borrachas
Console.WriteLine($"Acabando: {acabando.Count()}");

var foto = estoque.Where(p => p.Quantidade < 5).ToList();
estoque[2] = estoque[2] with { Quantidade = 10 };   // chegaram mochilas
Console.WriteLine($"Acabando (consulta): {acabando.Count()}");
Console.WriteLine($"Acabando (ToList):   {foto.Count}");

record Produto(int Codigo, string Nome, string Categoria, int Quantidade, decimal Preco);

$ dotnet run
Acabando: 2
Acabando: 1
Acabando (consulta): 0
Acabando (ToList):   1

A mesma variável acabando deu 2, depois 1, depois 0, porque cada Count() refez o filtro na lista do momento. Isso se chama execução adiada. Quando você quer guardar o resultado daquele momento, termine a consulta com .ToList(): ela roda na hora e copia os produtos para uma lista nova. Aula: O que é LINQ.

Versão 3 · O relatório por categoria e a busca

Agora a Ana quer o relatório do fim do mês: para cada categoria, quantos produtos, quantas unidades e quanto vale. No caderno, ela faria três pilhas de fichas (Papelaria, Escrita, Bolsas) e somaria cada pilha. O GroupBy ("agrupar por") faz exatamente as pilhas.

// Estoque da Lojinha — versão 3: relatório por categoria e busca
List<Produto> estoque =
[
    new(1, "Caderno", "Papelaria", 12, 15.90m),
    new(2, "Caneta", "Escrita", 40, 2.50m),
    new(3, "Borracha", "Escrita", 3, 1.75m),
    new(4, "Mochila", "Bolsas", 2, 89.90m),
    new(5, "Lápis", "Escrita", 60, 1.20m),
    new(6, "Papel A4", "Papelaria", 4, 27.50m),
    new(7, "Estojo", "Bolsas", 6, 19.90m),
];

// Relatório: uma linha por categoria, da que vale mais para a que vale menos
var relatorio = estoque
    .GroupBy(p => p.Categoria)
    .Select(g => new
    {
        Categoria = g.Key,
        Produtos = g.Count(),
        Unidades = g.Sum(p => p.Quantidade),
        Valor = g.Sum(p => p.Quantidade * p.Preco)
    })
    .OrderByDescending(c => c.Valor);

Console.WriteLine("Categoria   Produtos  Unidades       Valor");
foreach (var c in relatorio)
{
    Console.WriteLine($"{c.Categoria,-10}  {c.Produtos,8}  {c.Unidades,8}  {c.Valor,10:C}");
}

// Busca pelo nome, sem ligar para maiúsculas
Mostrar(Buscar(estoque, "caneta"));
Mostrar(Buscar(estoque, "régua"));

bool temBolsa = estoque.Any(p => p.Categoria == "Bolsas");
bool tudoTem = estoque.All(p => p.Quantidade > 0);
Console.WriteLine($"Vende bolsas? {temBolsa}. Nada esgotado? {tudoTem}.");

static Produto? Buscar(List<Produto> lista, string nome) =>
    lista.FirstOrDefault(p => p.Nome.Equals(nome, StringComparison.OrdinalIgnoreCase));

static void Mostrar(Produto? p)
{
    if (p is null)
    {
        Console.WriteLine("Não temos esse produto.");
        return;
    }
    Console.WriteLine($"{p.Nome}: {p.Quantidade} unidades a {p.Preco:C}");
}

static void Movimentar(List<Produto> lista, int sinal)
{
    if (!int.TryParse(Perguntar("Código: "), out int codigo))
    {
        Console.WriteLine("Código inválido.");
        return;
    }
    int i = lista.FindIndex(p => p.Codigo == codigo);
    if (i == -1)
    {
        Console.WriteLine($"Não há produto com o código {codigo}.");
        return;
    }
    if (!int.TryParse(Perguntar("Quantas unidades? "), out int qtd) || qtd <= 0)
    {
        Console.WriteLine("Quantidade inválida.");
        return;
    }
    Produto p = lista[i];
    if (sinal < 0 && qtd > p.Quantidade)
    {
        Console.WriteLine($"Só há {p.Quantidade} de {p.Nome}.");
        return;
    }
    lista[i] = p with { Quantidade = p.Quantidade + sinal * qtd };
    Console.WriteLine($"{p.Nome}: agora são {lista[i].Quantidade}.");
}

static List<Produto> Carregar()
{
    if (!File.Exists(Arquivo))
    {
        Console.WriteLine($"{Arquivo} não existe: começando do caderno de papel.");
        return
        [
            new(1, "Caderno", "Papelaria", 12, 15.90m),
            new(2, "Caneta", "Escrita", 40, 2.50m),
            new(3, "Borracha", "Escrita", 3, 1.75m),
            new(4, "Mochila", "Bolsas", 2, 89.90m),
            new(5, "Lápis", "Escrita", 60, 1.20m),
            new(6, "Papel A4", "Papelaria", 4, 27.50m),
            new(7, "Estojo", "Bolsas", 6, 19.90m),
        ];
    }
    return File.ReadLines(Arquivo)
        .Skip(1)                                   // pula o cabeçalho
        .Where(linha => linha.Trim() != "")        // ignora linhas vazias
        .Select(LerLinha)
        .ToList();
}

static Produto LerLinha(string linha)
{
    string[] c = linha.Split(';');
    return new Produto(int.Parse(c[0]), c[1], c[2], int.Parse(c[3]),
                       decimal.Parse(c[4], CultureInfo.InvariantCulture));
}

static void Salvar(List<Produto> lista)
{
    var linhas = lista.Select(p => string.Join(";", p.Codigo, p.Nome, p.Categoria, p.Quantidade,
                                               p.Preco.ToString(CultureInfo.InvariantCulture)));
    File.WriteAllLines(Arquivo, linhas.Prepend("codigo;nome;categoria;quantidade;preco"));
}

Resumo

  • Um record descreve a ficha; uma List<Produto> guarda todas. Para "mudar" um record, crie uma cópia com with.
  • Where filtra, OrderBy ordena, Select transforma, Count e Sum fazem contas, MaxBy acha o maior, Any e All respondem sim ou não.
  • GroupBy faz uma pilha por chave (g.Key); cada pilha aceita as mesmas contas.
  • First lança exceção se não acha; FirstOrDefault devolve null, e você confere.
  • Uma consulta LINQ roda de novo a cada uso; ToList() tira uma "foto" na hora.
  • Não mude a lista dentro do foreach que a percorre: use RemoveAll ou crie uma lista nova.
  • Em arquivos, grave e leia números com CultureInfo.InvariantCulture, e separe campos com um caractere que não aparece nos dados.
