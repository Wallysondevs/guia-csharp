C# Novidades do C# 8 ao 14

O C# ganha uma versão nova todo ano, em novembro, junto com o .NET. Muito do que este guia ensina como "o jeito normal" (dotnet run ola.cs sem class Program, [1, 2, 3], record, is not null) não existia há poucos anos, e você ainda vai encontrar muito código no estilo antigo. Esta aula é um mapa: o que entrou em cada versão, do C# 8 (2019) ao C# 14 (2025), onde cada coisa é ensinada no guia e, com mais detalhe, as novidades do C# 14, conferidas uma a uma no .NET 10 da máquina da Ana.

Você vai aprender
  • A relação entre a versão do C# e a do .NET, e o que é o LangVersion (erro CS9260).
  • A tabela das novidades do C# 8 ao 13, com um programa que usa várias delas.
  • O C# 14 na prática: a palavra field, os blocos extension, a atribuição condicional nula ?.=, nameof(List<>), lambdas com out e ref sem tipos, construtores partial, operadores += e spans de primeira classe.
  • As armadilhas: um campo chamado field (CS9258) e o ?. com ++ (CS1059).

Esta aula passa por muitos assuntos do guia e aponta a aula de cada um. Vale a pena voltar a ela depois de terminar o Nível 3. Os exemplos rodaram com dotnet run no .NET 10 (dotnet --version = 10.0.112) da máquina da Ana, na pasta ~/cs.

A ideia antes do código: linguagem × plataforma

Lembre a diferença entre o C# (a linguagem: as palavras e regras que você escreve) e o .NET (a plataforma: o compilador, as bibliotecas e o runtime que roda o programa), da aula .NET: SDK, Runtime e CLR. Cada .NET vem com um compilador que entende uma versão do C#, e cada projeto escolhe a versão da linguagem pelo .NET de destino:

Um programa, várias versões

Este programa da lojinha usa um recurso de quase cada versão. Os comentários dizem de qual:

// C# 9: instruções de nível superior (sem class Program nem Main)
List<Produto> estoque = [new("Caderno", 15.90m), new("Caneta", 2.50m)];   // C# 12: [ ]

string? aviso = null;
aviso ??= "sem avisos";                                // C# 8: ??=
Console.WriteLine(aviso);

foreach (var p in estoque)
{
    string faixa = p.Preco switch                       // C# 8: expressão switch
    {
        < 5 => "barato",                                // C# 9: padrões relacionais
        _ => "normal",
    };
    Console.WriteLine($"{p.Nome}: {faixa}");
}

Console.WriteLine(estoque is [var primeiro, ..] ? $"Primeiro: {primeiro.Nome}" : "vazio");   // C# 11

string json = """
    { "loja": "Ana", "aberta": true }
    """;                                                // C# 11: raw string
Console.WriteLine(json);

Caixa caixa = new("Ana");                               // C# 12: construtor primário
Console.WriteLine(caixa.Somar(10m, 5.5m, 2m));          // C# 13: params com coleções

{

    {

        foreach (var v in valores) total += v;
        return $"{operadora} somou {total}";

3. A palavra field C# 14

Uma propriedade automática ({ get; set; }) tem um campo escondido, que o compilador cria. Até o C# 13, se você quisesse validar o valor no set, precisava desistir da propriedade automática e escrever o campo à mão (private decimal _preco;). No C# 14, a palavra field ("campo") é esse campo escondido, e você pode usá-la dentro do get ou do set:

Produto p = new() { Nome = "  caderno  ", Preco = -5 };
Console.WriteLine($"[{p.Nome}] custa {p.Preco}");
p.Preco = 15.90m;
Console.WriteLine($"[{p.Nome}] custa {p.Preco}");

class Produto
{
    public string Nome
    {
        get;
        set => field = value.Trim();
    } = "";

    public decimal Preco
    {
        get;
        set => field = value < 0 ? 0 : value;
    }
}

$ dotnet run field.cs
[caderno] custa 0
[caderno] custa 15,90
get;
O get continua automático: devolve o campo escondido.
set => field = value.Trim();
O set tem corpo: tira os espaços das pontas e grava no campo escondido, que agora tem nome: field.
} = "";
O valor inicial vai para o mesmo campo.
value < 0 ? 0 : value
Preço negativo vira 0. Por isso o -5 do inicializador virou 0.

Antes, seriam 6 linhas a mais: private string _nome = "";, get => _nome;, set => _nome = value.Trim();, e o mesmo para o preço. E o campo _nome ficaria visível para o resto da classe, que poderia gravar nele sem passar pela validação. O field só existe dentro da propriedade.

Missão: uma nota precisa ficar entre 0 e 10. Troque o set; por um set que use field e Math.Clamp(value, 0, 10) ("prender" o valor na faixa). A saída deve ser Nota: 10, Nota: 0 e Nota: 7.

Console.WriteLine($"Nota: {a.Nota}");
a.Nota = -3;
Console.WriteLine($"Nota: {a.Nota}");
a.Nota = 7;
Console.WriteLine($"Nota: {a.Nota}");

class Aluno
{
    public int Nota { get; set; }
}

Aluno a = new();
a.Nota = 15;
Console.WriteLine($"Nota: {a.Nota}");
a.Nota = -3;
Console.WriteLine($"Nota: {a.Nota}");
a.Nota = 7;
Console.WriteLine($"Nota: {a.Nota}");

class Aluno
{
    public int Nota { get; set => field = Math.Clamp(value, 0, 10); }
}

4. Blocos extension C# 14

Os métodos de extensão (com this no primeiro parâmetro) existem desde o C# 3, mas só serviam para métodos. O C# 14 trouxe uma forma nova: um bloco extension(tipo nome) { … } dentro de uma classe estática, onde cabem também propriedades de extensão e membros estáticos de extensão:

string frase = "a lojinha da Ana";
Console.WriteLine(frase.Palavras);
Console.WriteLine(frase.Iniciais());
Console.WriteLine(string.Repetir("-", 10));
int[] vazio = [];
Console.WriteLine(vazio.EstaVazia);

static class ExtensoesDeTexto
{
    extension(string s)
    {
        public int Palavras => s.Split(' ', StringSplitOptions.RemoveEmptyEntries).Length;

        public string Iniciais() => string.Concat(s.Split(' ', StringSplitOptions.RemoveEmptyEntries).Select(p => char.ToUpper(p[0])));

        public static string Repetir(string pedaco, int vezes) => string.Concat(Enumerable.Repeat(pedaco, vezes));
    }

    extension<T>(IEnumerable<T> itens)
    {
        public bool EstaVazia => !itens.Any();
    }
}

5. Atribuição condicional nula: ?.= C# 14

O operador ?. (veja ?. e ??) já servia para ler sem medo de null: cliente?.Nome dá null se cliente for nulo, em vez de lançar exceção. No C# 14, ele também serve para gravar: cliente?.Pontos = 10; grava se cliente existir e não faz nada se ele for nulo.

Cliente? ana = new() { Nome = "Ana" };
Cliente? ninguem = null;

ana?.Pontos = 10;
ninguem?.Pontos = 10;
ana?.Pontos += 5;
ninguem?.Pontos += 5;

Console.WriteLine(ana?.Pontos);
Console.WriteLine(ninguem?.Pontos is null ? "ninguém, nada aconteceu" : "?");

int[]? notas = [7, 8];
notas?[0] = 10;
Console.WriteLine(notas?[0]);

class Cliente
{
    public string Nome { get; set; } = "";
    public int Pontos { get; set; }
}

$ dotnet run nulo.cs
15
ninguém, nada aconteceu
10
ana?.Pontos = 10;
"Se ana não for nulo, grave 10 em Pontos." Antes: if (ana is not null) ana.Pontos = 10;.
ninguem?.Pontos = 10;
ninguem é null: a linha não faz nada, e não há NullReferenceException.
ana?.Pontos += 5;
Também vale com +=, -= e companhia: 10 + 5 = 15.
notas?[0] = 10;
E com colchetes: o ?[ ] grava no array só se ele existir.

Um detalhe importante: o lado direito só é calculado se o objeto não for nulo. Em ninguem?.Pontos = CalcularPontos();, o método CalcularPontos nem é chamado.

6. As outras novidades do C# 14

nameof com genéricos abertos

O nameof devolve o nome de algo como texto, conferido pelo compilador. Até o C# 13, para um tipo genérico era preciso inventar um tipo qualquer (nameof(List<int>)). Agora dá para deixar os <> vazios:

Console.WriteLine(nameof(List<>));
Console.WriteLine(nameof(Dictionary<,>));
Console.WriteLine(nameof(List<>.Count));
Console.WriteLine(nameof(List<int>));

$ dotnet run nomes.cs
List
Dictionary
Count
List

Repare que o resultado é só o nome, sem os <>, nas duas formas. A vírgula em Dictionary<,> diz "dois parâmetros de tipo".

Parâmetros de lambda com out e ref, sem tipos

Numa lambda, o C# descobre os tipos dos parâmetros pelo delegate. Mas, se um parâmetro tinha out ou ref, era obrigatório escrever todos os tipos: (string texto, out int numero) => …. No C# 14, o modificador basta:

Conversor conv = (texto, out numero) => int.TryParse(texto, out numero);

foreach (var t in new[] { "42", "abc" })
{
    bool ok = conv(t, out int n);
    Console.WriteLine($"{t}: {(ok ? n : "inválido")}");
}

Dobrar dobrar = (ref x) => x *= 2;
int v = 21;
dobrar(ref v);
Console.WriteLine(v);

delegate bool Conversor(string texto, out int numero);
delegate void Dobrar(ref int x);

$ dotnet run lambda.cs
42: 42
abc: inválido
42

O delegate Conversor já diz que texto é string e numero é out int; a lambda só repete o out. O ref x da segunda lambda dobra a variável original (veja ref, out e in): 21 virou 42.

Construtores e eventos partial

As classes parciais podem ter partes em arquivos diferentes, e desde o C# 13 propriedades também podem ser declaradas numa parte e implementadas em outra. O C# 14 estendeu isso a construtores e eventos. É um recurso pensado para geradores de código, como o do [GeneratedRegex]:

Conta c = new(100m);
Console.WriteLine(c.Saldo);

partial class Conta
{
    public decimal Saldo { get; }
    public partial Conta(decimal inicial);
}

partial class Conta
{
    public partial Conta(decimal inicial)
    {
        Saldo = inicial;
    }
}

$ dotnet run parcial.cs
100

Operadores += e spans de primeira classe

Os dois têm aula própria: o public void operator +=(…) de instância está em Sobrecarga de Operadores (seção 5), e a conversão automática de array para ReadOnlySpan em métodos de extensão está em Span<T> (seção 3), com o erro CS1929 que o mesmo código dá no C# 13.

Quando dá errado

error CS9260: recurso novo numa versão antiga

Mensagem: O recurso "…" não está disponível no C# 13.0. Use a versão da linguagem 14.0 ou superior. (veja "A ideia antes do código"). Como consertar: tire o <LangVersion> do .csproj (o padrão do .NET 10 é o C# 14) ou, se o projeto precisa mesmo da versão antiga, escreva do jeito antigo. Atenção: os blocos extension numa versão antiga nem chegam a dar CS9260; o compilador não reconhece a sintaxe e mostra erros confusos, como CS1513: } esperada.

Uma classe que já tinha um campo chamado field

c.Valor = 7;
Console.WriteLine(c.Valor);
Console.WriteLine(c.CampoAntigo);

{

    public int CampoAntigo => this.field;
    public int Valor
    {
        get => field;
        set => field = value;
    }
}

O que quer dizer: num código escrito antes do C# 14, field era um nome comum. Agora, dentro de uma propriedade, ele é a palavra nova: o Valor passou a usar um campo escondido, e o campo field da linha 8 ficou esquecido (por isso CampoAntigo mostrou 0). O compilador avisa com CS9258. Como consertar: se você quer o campo antigo, escreva this.field ou @field dentro da propriedade, como a mensagem sugere; melhor ainda, renomeie o campo para _valor.

?. com ++

Este código tem um erro de propósito.

$ dotnet run mais.cs

Resumo

  • Cada .NET traz uma versão do C#: .NET 8 → C# 12, .NET 9 → C# 13, .NET 10 → C# 14 (LTS, até 2028). Um recurso mais novo que o <LangVersion> do projeto dá CS9260, dizendo o nome do recurso e a versão necessária.
  • Do C# 8 ao 13, a linguagem ganhou referências anuláveis, expressões switch, índices ^, records, instruções de nível superior, padrões cada vez mais ricos, strings brutas, required, expressões de coleção, construtores primários e params com spans.
  • C# 14: field nas propriedades (cuidado com campos chamados field: CS9258), blocos extension com propriedades e membros estáticos, obj?.Prop = valor (e +=, mas não ++: CS1059), nameof(List<>), lambdas (x, out y) =>, construtores e eventos partial, operator += e spans de primeira classe.
  • Todos os exemplos do C# 14 desta aula foram conferidos no .NET 10 do laboratório e no editor do guia.
