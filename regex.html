C# Expressões Regulares (Regex)

Uma expressão regular (em inglês regular expression, apelidada de regex) é um texto que descreve um formato: "cinco dígitos, um hífen e mais três dígitos" é o formato de um CEP. Com ela, o C# responde perguntas como "este texto tem cara de CEP?", "onde estão os preços neste recibo?" e "troque todos os espaços repetidos por um só". Tudo isso mora na classe Regex.

Você vai aprender
  • Os blocos de uma regex: \d, \w, [A-Z], +, {5}, ^, $, ( )…
  • Por que em C# se escreve a regex com @"…" (e o erro CS1009 sem ele).
  • Regex.IsMatch, e por que ele precisa de ^ e $ para validar o texto inteiro.
  • Match e Matches para achar pedaços, e grupos (numerados e com nome) para separar as partes.
  • Regex.Replace (com $1), Regex.Split, RegexOptions.IgnoreCase e o [GeneratedRegex].
  • As armadilhas: o .* guloso, o \d que aceita algarismos árabes e a RegexParseException.

Esta aula usa os métodos de string, os escapes e strings literais (@) e o foreach. Os exemplos rodaram com dotnet run no .NET 10 da máquina da Ana, na pasta ~/cs.

A ideia antes do código

Quando a Ana olha para 01310-100, ela reconhece um CEP sem pensar: "são 5 números, um tracinho, 3 números". Se alguém escrever 1310-100, ela estranha: falta um número. Ela não decorou todos os CEPs do Brasil; ela conhece o molde.

Uma regex é esse molde escrito numa linguagem que o computador entende. O molde do CEP fica assim:

^
"Aqui começa o texto." Nada pode vir antes.
\d
Um dígito (de digit): qualquer caractere de 0 a 9.
{5}
O item anterior, exatamente 5 vezes.
-
Um hífen de verdade. Letras e símbolos comuns representam eles mesmos.
\d{3}
Mais três dígitos.
$
"Aqui termina o texto." Nada pode vir depois.

Juntando: ^\d{5}-\d{3}$. A regex é uma linguagem pequena e própria, que existe também no grep do Linux, no JavaScript, no Python e no Java. O que você aprender aqui vale em quase todo lugar, com pequenas diferenças.

1. A primeira regex: Regex.IsMatch

A classe Regex fica em System.Text.RegularExpressions. O método IsMatch ("casa?") responde true ou false. Compare a regex sem e com ^ e $:

using System.Text.RegularExpressions;

string[] ceps = ["01310-100", "1310-100", "50030-23O", "Meu CEP é 50030-230, ok?"];
foreach (var cep in ceps)
{
    bool qualquerLugar = Regex.IsMatch(cep, @"\d{5}-\d{3}");
    bool inteiro = Regex.IsMatch(cep, @"^\d{5}-\d{3}$");
    Console.WriteLine($"{cep,-26} contém: {qualquerLugar,-5}  é um CEP: {inteiro}");
}

$ dotnet run cep.cs

1310-100                   contém: False  é um CEP: False
50030-23O                  contém: False  é um CEP: False
Meu CEP é 50030-230, ok?   contém: True   é um CEP: False

A pasta da classe Regex.
Regex.IsMatch(cep, …)
Primeiro o texto a examinar, depois a regex.
@"\d{5}-\d{3}"
A regex, numa string literal (@): a barra \ fica como está (seção 2).

Só formatação: alinha o texto em 26 colunas, para a tabela ficar bonita.

A última linha é a lição mais importante desta aula: IsMatch procura o molde em qualquer lugar do texto. "Meu CEP é 50030-230, ok?" contém um CEP, então a regex sem âncoras disse True. Para validar um campo (o texto inteiro tem de ser um CEP), use ^ no começo e $ no fim. E repare no 50030-23O: o último caractere é a letra O, não o zero, e o \d não deixou passar.

Quem vem do Java, atenção

O matches do Java confere o texto inteiro sozinho. O Regex.IsMatch do C# não: ele faz o papel do find. Sem ^ e $, a validação deixa passar lixo antes e depois.

Missão: o validador está aceitando CEP 01310-100 e 01310-1000, que não são CEPs. Acrescente as âncoras ^ e $ à regex para que só o primeiro e o último sejam aceitos.

using System.Text.RegularExpressions;

string[] testes = ["01310-100", "CEP 01310-100", "01310-1000", "50030-230"];
foreach (var t in testes)
{
    Console.WriteLine($"{t}: {Regex.IsMatch(t, @"\d{5}-\d{3}")}");
}

using System.Text.RegularExpressions;

string[] testes = ["01310-100", "CEP 01310-100", "01310-1000", "50030-230"];
foreach (var t in testes)
{
    Console.WriteLine($"{t}: {Regex.IsMatch(t, @"^\d{5}-\d{3}$")}");
}

2. Por que @"…": a barra invertida

Numa string comum do C#, a barra invertida já tem um trabalho: "\n" é uma quebra de linha, "\t" é uma tabulação. Mas \d não é um escape que o C# conheça, e o compilador reclama:

using System.Text.RegularExpressions;
Console.WriteLine(Regex.IsMatch("123", "\d+"));

$ dotnet run barra.cs
/home/ana/cs/barra.cs(2,41): error CS1009: Sequência de escape não reconhecida

Ocorreu uma falha no build. Corrija os erros de build e execute novamente.

Há duas saídas: dobrar a barra ("\\d+": o C# transforma \\ numa barra só, e a regex recebe \d+) ou usar uma string literal, com @ na frente, em que a barra é só uma barra. Com regex, use sempre @"…": fica igual ao que você vê em qualquer tutorial de regex.

using System.Text.RegularExpressions;
Console.WriteLine(Regex.IsMatch("123", "\\d+"));
Console.WriteLine(Regex.IsMatch("123", @"\d+"));
Console.WriteLine(Regex.IsMatch("١٢٣", @"^\d+$"));
Console.WriteLine(Regex.IsMatch("١٢٣", @"^[0-9]+$"));

$ dotnet run barras.cs
True
True
True
False

As duas primeiras linhas são a mesma regex escrita de dois jeitos. As duas últimas mostram uma surpresa: ١٢٣ são os algarismos 1, 2 e 3 do árabe, e o \d do .NET os aceita, porque segue o Unicode (todos os dígitos de todas as escritas). Se você vai converter o texto com int.Parse ou precisa só de 0 a 9 (CEP, CPF, telefone), escreva [0-9].

4. Achar pedaços: Match e Matches

Validar é só metade da história. A outra metade é procurar: achar todos os preços de um recibo, todos os e-mails de um texto. Regex.Match devolve o primeiro pedaço encontrado; Regex.Matches devolve todos.

using System.Text.RegularExpressions;

string recibo = "Caderno R$ 15,90; caneta R$ 2,50 (x3); mochila R$ 129,00";

MatchCollection precos = Regex.Matches(recibo, @"R\$ \d+,\d{2}");
Console.WriteLine($"Achei {precos.Count} preços:");
foreach (Match m in precos)
{
    Console.WriteLine($"  {m.Value} (na posição {m.Index})");
}

Match primeiro = Regex.Match(recibo, @"\d+,\d{2}");
Console.WriteLine($"Primeiro número: {primeiro.Value}");
Match nada = Regex.Match(recibo, @"US\$");
Console.WriteLine($"Achou dólar? {nada.Success}");

$ dotnet run recibo.cs

  R$ 129,00 (na posição 47)

Missão: o pedido chegou como texto. Use Regex.Matches com @"\d+" para achar todos os números, some-os com int.Parse(m.Value) e mostre Total de itens: 26.

5. Grupos: separar as partes

Os parênteses ( ) fazem duas coisas: agrupam (como na matemática) e capturam o pedaço que casou lá dentro, para você usar depois. Num telefone (81) 99999-0001, dá para pegar o DDD separado do número:

using System.Text.RegularExpressions;

string agenda = "Ana (81) 99999-0001, Bruno (11) 98888-0002, Carla 3333-4444";

foreach (Match m in Regex.Matches(agenda, @"\((\d{2})\) (\d{4,5})-(\d{4})"))
{
    Console.WriteLine($"Completo: {m.Value} | DDD: {m.Groups[1].Value} | número: {m.Groups[2].Value}-{m.Groups[3].Value}");
}

foreach (Match m in Regex.Matches(agenda, @"(?<nome>[A-Z][a-z]+) \((?<ddd>\d{2})\)"))
{
    Console.WriteLine($"{m.Groups["nome"].Value} mora no DDD {m.Groups["ddd"].Value}");
}

$ dotnet run telefones.cs
Completo: (81) 99999-0001 | DDD: 81 | número: 99999-0001
Completo: (11) 98888-0002 | DDD: 11 | número: 98888-0002
Ana mora no DDD 81
Bruno mora no DDD 11
\(
Um parêntese de verdade, o do telefone (com barra, porque ( sozinho abre um grupo).
(\d{2})
O grupo 1: dois dígitos, o DDD.
\)
O parêntese de verdade que fecha, e um espaço.
(\d{4,5})
O grupo 2: 4 ou 5 dígitos.
-(\d{4})
Um hífen e o grupo 3.
(?<ddd>\d{2})
Um grupo com nome: o mesmo que um grupo numerado, mas lido com m.Groups["ddd"], bem mais fácil de entender depois.

Os grupos são contados pelos parênteses que abrem, da esquerda para a direita. O m.Groups[0] é sempre o achado inteiro (o mesmo que m.Value). A Carla não apareceu: o telefone dela não tem DDD entre parênteses, então o molde não casou.

6. Trocar e dividir: Replace e Split

using System.Text.RegularExpressions;

string bagunca = "Lista   de    compras:  arroz,feijão ,  café";
Console.WriteLine(Regex.Replace(bagunca, @"\s+", " "));

string[] itens = Regex.Split("arroz,feijão ,  café;açúcar", @"\s*[,;]\s*");
Console.WriteLine(string.Join(" | ", itens));

string data = "Entrega em 25/12/2026 e troca até 10/01/2027.";
Console.WriteLine(Regex.Replace(data, @"(\d{2})/(\d{2})/(\d{4})", "$3-$2-$1"));

string cpf = "CPF 123.456.789-09";
Console.WriteLine(Regex.Replace(cpf, @"\d{3}\.\d{3}\.(\d{3})-(\d{2})", "***.***.$1-$2"));

Console.WriteLine(Regex.Replace("ana maria silva", @"\b[a-z]", m => m.Value.ToUpper()));

Console.WriteLine(Regex.IsMatch("CAFÉ", "café", RegexOptions.IgnoreCase));

Regex.Split(…, @"\s*[,;]\s*")Divide nas vírgulas ou pontos e vírgulas, engolindo os espaços em volta.

7. Reutilizar a regex: o objeto Regex e o [GeneratedRegex]

Os métodos estáticos (Regex.IsMatch(texto, molde)) são práticos: o .NET guarda as últimas regex usadas e não as reprocessa toda vez. Quando a mesma regex é usada muitas vezes, o costume é criá-la uma vez só e guardar:

static readonly Regex Cep = new(@"^\d{5}-\d{3}$");
// depois: Cep.IsMatch(texto)

Desde o .NET 7, existe um jeito ainda melhor: o atributo [GeneratedRegex]. Um gerador de código lê a regex na hora de compilar e escreve um código C# especializado para ela (mais rápido, e um erro na regex vira erro de compilação). Desde o C# 13 ele também funciona em propriedades partial:

using System.Text.RegularExpressions;

string[] testes = ["01310-100", "abc"];
foreach (var t in testes)
    Console.WriteLine($"{t}: {Validador.Cep.IsMatch(t)} {Validador.CepAntigo().IsMatch(t)}");

static partial class Validador
{
    [GeneratedRegex(@"^\d{5}-\d{3}$")]
    public static partial Regex Cep { get; }

    [GeneratedRegex(@"^\d{5}-\d{3}$")]
    public static partial Regex CepAntigo();
}

$ dotnet run gerada.cs
01310-100: True True
abc: False False

Você só escreve a "metade de cima" (partial, sem corpo); o gerador escreve a outra metade, com a regex já transformada em código. A forma com método (CepAntigo()) é a do .NET 7 e 8, e você vai vê-la muito.

O [GeneratedRegex] não roda no editor do guia

O editor desta página usa o compilador C# de verdade, mas não roda geradores de código. Lá, o gerada.cs não compila: a "metade de baixo" nunca é escrita, e aparecem os erros CS9248: A propriedade parcial "Validador.Cep" precisa ter uma parte de implementação e CS8795 para o método. No dotnet run e em projetos, funciona normalmente. Por isso os exercícios desta página usam os métodos estáticos.

O .* guloso pegou demais

using System.Text.RegularExpressions;
string html = "<b>Ana</b> e <b>Bruno</b>";
Console.WriteLine(Regex.Match(html, "<b>.*</b>").Value);
Console.WriteLine(Regex.Match(html, "<b>.*?</b>").Value);

O que quer dizer: a Ana queria só o primeiro nome em negrito, mas o .* é guloso: pega o máximo possível e só para no último </b>. Como consertar: o ? depois do * (ou do +) o torna preguiçoso: .*? pega o mínimo e para no primeiro </b>. (Para HTML de verdade, use uma biblioteca de HTML; regex serve para casos simples.)

A validação deixou passar lixo

Regex.IsMatch("CEP 01310-100", @"\d{5}-\d{3}") deu True. O que quer dizer: sem âncoras, o IsMatch procura em qualquer lugar (seção 1). Como consertar: @"^\d{5}-\d{3}$". E lembre do \d que aceita ١٢٣: para "só 0 a 9", use [0-9].

Resumo

  • Uma regex é um molde de texto: \d dígito, \w letra, \s espaço, [a-z] faixa, + * ? {n,m} repetições, ^ $ começo e fim, ( ) grupos, \. o símbolo de verdade.
  • Em C#, escreva a regex com @"…" (sem ele, "\d" dá CS1009) e use as classes de System.Text.RegularExpressions.
  • Regex.IsMatch procura em qualquer lugar: para validar o texto inteiro, use ^…$. Para só 0 a 9, [0-9] (o \d aceita dígitos de outras escritas).
  • Match (primeiro, com Success) e Matches (todos) acham pedaços; Groups[1] ou Groups["nome"] separam as partes.
  • Regex.Replace troca (com $1 ou uma lambda) e Regex.Split divide. .* é guloso; .*? é preguiçoso.
  • Regex errada é RegexParseException ao rodar. [GeneratedRegex] transforma a regex em código na compilação (no dotnet; o editor do guia não roda geradores).
