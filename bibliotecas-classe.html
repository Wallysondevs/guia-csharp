C# Bibliotecas de Classes

A Ana escreveu as regras do boletim da escola: lançar notas, calcular a média, dizer se o aluno passou. Agora ela quer usar essas mesmas regras em dois programas: o que a professora usa para lançar as notas e o que imprime o relatório da turma. Copiar o código para os dois seria pedir problema: uma correção num, esquecida no outro. A saída é pôr as regras numa biblioteca de classes: um projeto que não roda sozinho, só serve para outros projetos usarem.

Você vai aprender
  • A criar uma biblioteca com dotnet new classlib e o que muda no .csproj.
  • O que outro projeto enxerga: public × internal e o erro CS0122.
  • A ligar a biblioteca a um programa (dotnet reference add) e onde o .dll dela vai parar.
  • A usar a mesma biblioteca em dois programas.
  • Como uma exceção da biblioteca aparece no programa.
  • A documentar a biblioteca com /// (e o aviso CS1591) e a empacotá-la com dotnet pack.

Todas as saídas desta aula são reais, feitas com o .NET 10 SDK (10.0.112) na máquina fictícia da Ana, na solução ~/projetos/Escola. Antes, leia Soluções e Vários Projetos, que mostra a solução e o dotnet reference add.

A ideia: a caixa de ferramentas

Um eletricista não fabrica uma chave de fenda para cada serviço. Ele tem uma caixa de ferramentas e a leva para todas as casas. A caixa não faz nada sozinha: quem trabalha é o eletricista, usando as ferramentas dela.

Na oficinaNo .NET
A caixa de ferramentasA biblioteca de classes (Escola.Notas): classes prontas, sem Main
Cada serviço numa casaCada programa (Escola.App, Escola.Relatorio): tem por onde começar a rodar
As ferramentas que ficam à mostraAs classes public
As peças de dentro da caixa (que o cliente não mexe)As classes internal
Uma caixa vendida na lojaUm pacote NuGet (dotnet pack)

Você já usa bibliotecas o tempo todo: Console, List<T> e File moram em bibliotecas do .NET, e o Humanizer da aula Pacotes NuGet é uma biblioteca de outra pessoa. Agora você vai escrever a sua.

O modelo "Biblioteca de Classes" (class library). O > /dev/null só esconde as mensagens de sempre do dotnet new.
sem <OutputType>
Compare com o .csproj de um console (veja O Arquivo .csproj): falta a linha <OutputType>Exe</OutputType>. Sem ela, o padrão é Library: o resultado é só um .dll, sem executável.
Class1.cs
Uma classe vazia de exemplo, no lugar do Program.cs. Não há instruções de nível superior: uma biblioteca só tem classes (e outros tipos).
namespace Escola.Notas;
O namespace vem do nome do projeto. É por ele que os outros projetos vão chamar as classes (using Escola.Notas;, veja Namespaces e using).

Uma biblioteca não roda:

$ dotnet run
Não é possível continuar com o projeto "/home/ana/projetos/Escola/src/Escola.Notas/Escola.Notas.csproj".
Verifique se você tem um tipo de projeto executável.
Um projeto executável deve ter como destino um TFM executável (por exemplo, net10.0) e ter OutputType "Exe".
O OutputType atual é "Library".

A mensagem é clara: para rodar, o projeto precisaria de OutputType Exe (o "TFM" é o Target Framework Moniker, o net10.0 do TargetFramework). Mas a biblioteca não é para rodar: é para ser usada.

2. As classes da biblioteca: public e internal

A Ana apagou o Class1.cs e escreveu dois arquivos. O primeiro é a classe que os programas vão usar:

namespace Escola.Notas;

public class Boletim(string aluno)
{
    private readonly List<decimal> _notas = [];

    public string Aluno { get; } = aluno;

    public void Lancar(decimal nota)
    {
        if (nota < 0 || nota > 10)
        {
            throw new ArgumentOutOfRangeException(nameof(nota), "A nota vai de 0 a 10.");
        }
        _notas.Add(nota);
    }

    public decimal Media => _notas.Count == 0 ? 0 : Regras.Arredondar(_notas.Average());

    public string Situacao => Media >= Regras.MediaMinima ? "Aprovado" : "Recuperação";
}

O segundo guarda as regras da escola, que só o Boletim usa:

namespace Escola.Notas;

internal static class Regras
{
    public const decimal MediaMinima = 7.0m;

    public static decimal Arredondar(decimal valor) => Math.Round(valor, 1);
}
public class Boletim
public ("público"): a classe fica visível para os outros projetos que usarem a biblioteca. É a "ferramenta à mostra".
internal static class Regras
internal ("interno"): visível só dentro deste projeto. O Boletim usa as Regras, mas os programas não enxergam essa classe. Assim, a Ana pode mudar as regras (o arredondamento, a média mínima) sem quebrar nenhum programa.
sem modificador
Uma classe sem public nem internal é internal. Por isso, numa biblioteca, esquecer o public deixa a classe invisível para os programas (veja Modificadores de Acesso).
throw new ArgumentOutOfRangeException(…)
A biblioteca não sabe se está num console, num site ou num celular, então ela não escreve mensagens na tela: ela lança uma exceção e deixa o programa decidir o que mostrar (veja throw).
ModificadorQuem enxergaUse para
publicTodo mundo: este projeto e quem o referenciarO que os programas devem usar (o Boletim)
internal (o padrão das classes)Só o próprio projetoOs detalhes de dentro (as Regras)
private (o padrão dos membros)Só a própria classeOs campos (_notas)

4. A mesma biblioteca em dois programas

var ana = new Boletim("Ana");
ana.Lancar(8.5m); ana.Lancar(6.0m); ana.Lancar(9.25m);
turma.Add(ana);

var beto = new Boletim("Beto");
beto.Lancar(5.0m); beto.Lancar(7.5m);
turma.Add(beto);

foreach (Boletim b in turma.OrderByDescending(b => b.Media))
{
    Console.WriteLine($"{b.Aluno,-6} {b.Media,4} {b.Situacao}");
}

A solução agora tem três projetos: uma biblioteca e dois programas que a usam. Se a escola mudar a média mínima para 6,0, a Ana muda uma linha em Regras.cs, e os dois programas passam a seguir a regra nova no próximo dotnet build.

Repare na média do Beto. (5,0 + 7,5) ÷ 2 = 6,25, e o Math.Round(6.25m, 1) deu 6,2, não 6,3. Quando o número está exatamente no meio, o Math.Round arredonda para o vizinho par (o "arredondamento bancário"). Se a escola quiser o arredondamento da escola (6,25 → 6,3), a regra vira Math.Round(valor, 1, MidpointRounding.AwayFromZero), e a mudança é numa linha só da biblioteca (veja Math).

Quando dá errado

error CS0122: "Regras" é inacessível devido ao seu nível de proteção 
$ echo 'Console.WriteLine(Regras.MediaMinima);' >> src/Escola.App/Program.cs
$ dotnet build 2>&1 | grep error | sort -u
/home/ana/projetos/Escola/src/Escola.App/Program.cs(9,19): error CS0122: "Regras" é inacessível devido ao seu nível de proteção [/home/ana/projetos/Escola/src/Escola.App/Escola.App.csproj]

O que aconteceu: o programa tentou usar a classe Regras, que é internal na biblioteca. O compilador sabe que ela existe, mas não deixa usar (em inglês, 'Regras' is inaccessible due to its protection level). Se a classe tivesse ficado sem modificador, o erro seria o mesmo, porque o padrão é internal.

Como resolver: se o programa precisa mesmo daquilo, torne public. Se não (como aqui), deixe internal e use o que a biblioteca oferece em público (Boletim.Situacao). Para um projeto de testes enxergar o internal, existe o atributo [assembly: InternalsVisibleTo("Escola.Notas.Tests")].

Não é possível continuar com o projeto … O OutputType atual é "Library".

O que aconteceu: o dotnet run foi chamado na pasta da biblioteca (seção 1).

Como resolver: rode o programa que usa a biblioteca: dotnet run --project src/Escola.App.

error CS0246: O nome do tipo ou do namespace "Escola" não pode ser encontrado

O que aconteceu: o programa não tem a referência para a biblioteca, ou falta o using Escola.Notas; (veja o mesmo erro em Soluções).

Como resolver: dotnet reference list --project src/Escola.App mostra as referências. Se a biblioteca não estiver lá: dotnet reference add src/Escola.Notas --project src/Escola.App.

6. Depois do dotnet build, onde está o Escola.Notas.dll que o Escola.App usa ao rodar?

Resumo

  • Uma biblioteca de classes (dotnet new classlib) é um projeto sem OutputType Exe: vira um .dll que não roda sozinho, só é usado.
  • public é o que os outros projetos enxergam; internal (o padrão das classes) fica dentro da biblioteca.
  • O programa usa a biblioteca com dotnet reference add e using. O build copia o .dll da biblioteca para a pasta do programa.
  • Uma biblioteca serve a vários programas: uma correção nela vale para todos.
  • A biblioteca lança exceções; o programa decide o que mostrar.
  • /// documenta; GenerateDocumentationFile gera o .xml e cobra o que falta (CS1591). dotnet pack cria um pacote NuGet.
