C# Reflexão

Normalmente, o programa usa as classes que você escreveu sem "saber" nada sobre elas: chama produto.Nome porque você escreveu produto.Nome. Com a reflexão (em inglês, reflection), o programa se olha no espelho enquanto roda: pergunta "de que tipo é este objeto?", "que propriedades ele tem?", "existe um método chamado Somar?", e pode até chamar esse método a partir de um texto. É assim que funcionam por dentro o System.Text.Json, os testes do xUnit e muitas outras bibliotecas.

Você vai aprender
  • O que é um Type e como obtê-lo com typeof e GetType().
  • Listar as propriedades de qualquer objeto e ler os valores (GetProperties, GetValue).
  • Achar um método pelo nome e chamá-lo (GetMethod, Invoke), e criar um objeto a partir do nome da classe.
  • Ler atributos para montar um validador de cadastro.
  • Por que a reflexão abre até campos private, por que ela é lenta e o que são os avisos IL2075 e IL2026.
  • As exceções NullReferenceException, TargetParameterCountException e TargetInvocationException.

Esta aula usa classes, propriedades, atributos e os operadores ?. e ??. Os exemplos rodaram com dotnet run no .NET 10 da máquina da Ana, na pasta ~/cs.

A ideia antes do código

Quando o C# compila o seu programa, ele não guarda só as instruções. Guarda também uma ficha de cada tipo: o nome da classe, as propriedades (com nome e tipo), os métodos (com os parâmetros), os atributos. Essa ficha se chama metadados ("dados sobre os dados").

Pense na ficha cadastral de um produto na lojinha da Ana: ela não é o produto, mas descreve tudo sobre ele. A reflexão é o jeito de o programa ler essas fichas enquanto roda. Com ela, dá para escrever um único método que mostra qualquer objeto na tela, sem saber de antemão de que classe ele é.

1. Type: a ficha de um tipo

A ficha é um objeto da classe Type (tipo). Há dois jeitos de pegá-la: typeof(Classe), quando você sabe o nome da classe ao escrever o código, e objeto.GetType(), quando você tem um objeto e quer saber o que ele é de verdade.

Produto caderno = new("Caderno", 15.90m, 12);

Type tipo = caderno.GetType();
Console.WriteLine(tipo.Name);
Console.WriteLine(tipo.FullName);
Console.WriteLine(tipo == typeof(Produto));
Console.WriteLine(tipo.BaseType);
Console.WriteLine(typeof(int).FullName);
Console.WriteLine(typeof(List<string>).Name);
Console.WriteLine(42.GetType().Name);
object coisa = "Ana";
Console.WriteLine(coisa.GetType().Name);

2. Listar as propriedades de qualquer objeto

A ficha sabe quais propriedades o tipo tem. GetProperties() devolve uma lista de PropertyInfo ("informação de propriedade"), e cada uma sabe o próprio nome, o tipo e como ler o valor num objeto. Com isso, a Ana escreve um Mostrar que funciona para produtos, clientes e qualquer outra classe:

using System.Reflection;

Mostrar(new Produto("Caderno", 15.90m, 12));
Mostrar(new Cliente { Nome = "Ana", Cidade = "Recife", Idade = 29 });

void Mostrar(object obj)
{
    Type tipo = obj.GetType();
    Console.WriteLine($"--- {tipo.Name} ---");
    foreach (PropertyInfo p in tipo.GetProperties())
    {
        object? valor = p.GetValue(obj);
        Console.WriteLine($"{p.Name} ({p.PropertyType.Name}) = {valor}");
    }
}

record Produto(string Nome, decimal Preco, int Estoque);

class Cliente
{
    public string Nome { get; set; } = "";
    public string Cidade { get; set; } = "";
    public int Idade { get; set; }
}

3. Achar e chamar um método pelo nome

A ficha também lista os métodos. E o mais curioso: dá para chamar um método cujo nome só se conhece enquanto o programa roda, por exemplo um nome digitado pelo usuário ou lido de um arquivo.

using System.Reflection;

Calculadora calc = new();
Type tipo = typeof(Calculadora);

foreach (MethodInfo m in tipo.GetMethods(BindingFlags.Public | BindingFlags.Instance | BindingFlags.DeclaredOnly))
{
    string parametros = string.Join(", ", m.GetParameters().Select(p => $"{p.ParameterType.Name} {p.Name}"));
    Console.WriteLine($"{m.ReturnType.Name} {m.Name}({parametros})");
}

string? escolha = "Multiplicar";
MethodInfo? metodo = tipo.GetMethod(escolha);
object? resultado = metodo?.Invoke(calc, [6, 7]);
Console.WriteLine($"{escolha}(6, 7) = {resultado}");

class Calculadora
{
    public int Somar(int a, int b) => a + b;
    public int Multiplicar(int a, int b) => a * b;
    public string Descrever() => "Calculadora da Ana";
}

$ dotnet run metodos.cs

Int32 Multiplicar(Int32 a, Int32 b)
String Descrever()
Multiplicar(6, 7) = 42
TrechoO que faz
GetMethods(BindingFlags.Public | BindingFlags.Instance | BindingFlags.DeclaredOnly)Os BindingFlags ("opções de busca") filtram a lista: métodos públicos, de instância (não static) e declarados nesta classe. Sem o DeclaredOnly, viriam também os herdados de object: ToString, Equals, GetHashCode, GetType.
m.GetParameters()Os parâmetros do método, cada um com nome e tipo.
tipo.GetMethod(escolha)Procura um método público com esse nome. Se não existir, devolve null.
metodo?.Invoke(calc, [6, 7])Chama o método no objeto calc, com os argumentos num array de object. O resultado vem como object?. O ?. evita o erro se o método não existir.

Criar um objeto a partir do nome

Type.GetType("Nome") procura um tipo pelo nome, e Activator.CreateInstance ("ativador, criar instância") faz um new nele:

Type? tipo = Type.GetType("Caderno");
Console.WriteLine(tipo?.Name ?? "não achei");
object? obj = Activator.CreateInstance(tipo!);
Console.WriteLine(obj);
Console.WriteLine(Type.GetType("Lapis")?.Name ?? "não achei");

Para um tipo que está dentro de um namespace, o nome completo é necessário: Type.GetType("Loja.Caderno"). Esse é o truque por trás de "plugins": o nome da classe vem de um arquivo de configuração, e o programa cria o objeto sem que o código mencione a classe.

4. Ler atributos: um validador de cadastro

Na aula de atributos, você viu que uma etiqueta só faz efeito quando alguém a lê. Agora você é esse alguém. A Ana cria duas etiquetas, [Obrigatorio] e [Faixa(min, max)], cola nas propriedades do Cadastro, e um Validar confere tudo lendo as etiquetas:

using System.Reflection;

Cadastro bom = new() { Nome = "Ana", Email = "ana@email.com", Idade = 29 };
Cadastro ruim = new() { Nome = "", Email = null, Idade = 200 };

Validar(bom);
Validar(ruim);

void Validar(object obj)
{
    Console.WriteLine($"Validando {obj.GetType().Name}...");
    int problemas = 0;
    foreach (PropertyInfo p in typeof(Cadastro).GetProperties())
    {
        object? valor = p.GetValue(obj);
        if (p.GetCustomAttribute<ObrigatorioAttribute>() is not null
            && (valor is null || valor is ""))
        {
            Console.WriteLine($"  {p.Name}: obrigatório");
            problemas++;
        }
        if (p.GetCustomAttribute<FaixaAttribute>() is { } faixa
            && valor is int n && (n < faixa.Minimo || n > faixa.Maximo))
        {
            Console.WriteLine($"  {p.Name}: {n} fora de {faixa.Minimo} a {faixa.Maximo}");
            problemas++;
        }
    }
    Console.WriteLine(problemas == 0 ? "  tudo certo" : $"  {problemas} problema(s)");
}

[AttributeUsage(AttributeTargets.Property)]
class ObrigatorioAttribute : Attribute { }

[AttributeUsage(AttributeTargets.Property)]
class FaixaAttribute(int minimo, int maximo) : Attribute
{
    public int Minimo { get; } = minimo;
    public int Maximo { get; } = maximo;
}

class Cadastro
{
    [Obrigatorio] public string Nome { get; set; } = "";
    [Obrigatorio] public string? Email { get; set; }
    [Faixa(0, 130)] public int Idade { get; set; }
}

Um padrão de propriedade vazio: "não é nulo, e chame-o de faixa". Assim dá para ler faixa.Minimo e faixa.Maximo.

Repare na divisão de trabalho: o Cadastro só declara as regras, com etiquetas, e o Validar as aplica. Se amanhã a Ana criar uma classe Fornecedor, basta etiquetar as propriedades. É exatamente assim que funcionam os [Required] e [Range] do ASP.NET.

5. A reflexão abre até o que é private

Com os BindingFlags certos, a reflexão enxerga e altera campos privados:

using System.Reflection;

Conta conta = new();
Console.WriteLine(conta);

FieldInfo? campo = typeof(Conta).GetField("_saldo", BindingFlags.NonPublic | BindingFlags.Instance);
campo?.SetValue(conta, 1_000_000m);
Console.WriteLine(conta);

class Conta
{
    private decimal _saldo = 50m;
    public override string ToString() => $"Saldo: {_saldo:N2}";
}

$ dotnet run privado.cs
Saldo: 50,00
Saldo: 1.000.000,00
private não é cadeado

O private protege o código de erros de quem programa, não de alguém mal-intencionado: qualquer código rodando no mesmo programa pode, com reflexão, mexer no que quiser. Nunca guarde uma senha num campo private achando que está segura. E não use esse truque no dia a dia: ele passa por cima do encapsulamento, e o seu programa quebra quando o autor da classe renomear o campo (o nome "_saldo" é só um texto, o compilador não confere). O uso legítimo é em ferramentas e testes.

6. O preço da reflexão

CustoO que acontece
Sem ajuda do compiladorOs nomes são textos: GetMethod("Multplicar") (com erro de digitação) compila e só falha ao rodar. O nameof(Calculadora.Multiplicar) ajuda: ele é conferido pelo compilador.
LentidãoProcurar um método e chamá-lo por Invoke custa bem mais que uma chamada normal (cada argumento vira object, há conferências a cada chamada). Num laço de milhões de voltas, faz diferença.
Programas enxugadosAo publicar com trimming ou Native AOT (veja Publicar o Programa), o que o compilador não vê sendo usado pode ser removido, e a reflexão pode não achar o que procura. Os avisos IL2075 e IL2026 avisam desses pontos.
Por que o dotnet run arquivo.cs mostra o IL2075?

Os programas de um arquivo só do .NET 10 (dotnet run arquivo.cs) já vêm preparados para serem publicados com Native AOT, e por isso os analisadores de trimming ficam ligados. O programa roda normalmente; o aviso é sobre uma futura publicação enxugada. Se o seu programa usa reflexão de propósito e você não pretende publicá-lo assim, desligue o modo AOT com uma linha no topo do arquivo: #:property PublishAot=false. Conferido no laboratório: com ela, o mostrar.cs roda sem o aviso. Num projeto (dotnet new console), o AOT vem desligado e o aviso não aparece.

Por isso, a regra prática: use reflexão quando não existe outro jeito, como em ferramentas genéricas (mostrar, salvar, validar qualquer objeto). Se você sabe o tipo, use o tipo: produto.Nome é mais rápido, mais seguro e o compilador confere. Muitas bibliotecas modernas trocaram a reflexão por geradores de código, que escrevem o código "normal" na hora de compilar (o System.Text.Json tem um, que a aula JSON menciona).

Quando dá errado

O método não existe: NullReferenceException

Este código tem um erro de propósito.
Calculadora calc = new();
var metodo = typeof(Calculadora).GetMethod("Dividir");
Console.WriteLine(metodo.Invoke(calc, [6, 0]));
class Calculadora
{
    public int Somar(int a, int b) => a + b;
}

$ dotnet run semmetodo.cs
/home/ana/cs/semmetodo.cs(3,19): warning CS8602: Desreferência de uma referência possivelmente nula.
Unhandled exception. System.NullReferenceException: Object reference not set to an instance of an object.
   at Program.<Main>$(String[] args) in /home/ana/cs/semmetodo.cs:line 3

O que quer dizer: não há método Dividir, então o GetMethod devolveu null, e chamar .Invoke em null quebrou. O compilador até avisou (CS8602): o GetMethod devolve MethodInfo?, que pode ser nulo. Como consertar: confira antes: if (metodo is null) { Console.WriteLine("Operação desconhecida"); return; }, ou use metodo?.Invoke(…). Não cale o aviso com ! sem ter certeza de que o método existe.

Este código tem um erro de propósito.

Resumo

  • Reflexão é o programa lendo, enquanto roda, as fichas (metadados) dos seus tipos. A ficha é um Type: typeof(T) ou obj.GetType(), que sempre conta o tipo real.
  • GetProperties() e GetValue(obj) percorrem as propriedades de qualquer objeto; GetMethod("Nome") e Invoke(obj, args) chamam um método pelo nome; Activator.CreateInstance cria objetos.
  • GetCustomAttribute<A>() lê atributos: é assim que validadores, serializadores e frameworks de teste funcionam.
  • Os erros de reflexão só aparecem ao rodar: null quando o nome não existe, TargetParameterCountException com argumentos errados, TargetInvocationException embrulhando a exceção do método chamado.
  • Reflexão é lenta, ignora o private e atrapalha programas enxugados (avisos IL2075/IL2026, que o dotnet run arquivo.cs mostra e o editor não). Use quando não houver outro jeito; se você conhece o tipo, use o tipo.
