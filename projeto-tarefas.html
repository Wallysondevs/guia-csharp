Projeto Lista de Tarefas

A Ana anota o que tem de fazer em papeizinhos colados na geladeira: "comprar pão", "estudar C#", "pagar a conta de luz". Os papéis caem, se perdem, e ela nunca sabe quantos ainda faltam. Neste projeto, ela escreve um programa de lista de tarefas: anota, marca como feita, apaga, e a lista continua lá no dia seguinte. É o primeiro projeto do guia com várias classes em vários arquivos, do jeito que os programas de verdade são organizados.

Você vai praticar
  • Escrever uma classe com propriedades, construtor e métodos, num arquivo próprio.
  • Proteger os dados com private set e private (Encapsulamento) e validar no construtor com throw.
  • Sobrescrever o ToString (aula A Classe object).
  • Usar uma List<T> por dentro de outra classe: Add, Find, RemoveAll.
  • Fazer um menu com switch e int.TryParse.
  • Guardar a lista num arquivo de texto com StreamWriter, using e File.ReadAllLines.

Versão 1 · A classe Tarefa

Um papelzinho da geladeira tem três coisas: um número (para a Ana dizer "fiz a 2"), o texto, e um risco quando a tarefa está feita. A classe Tarefa é o molde desse papel. Ela fica no arquivo Tarefa.cs:

// Tarefa.cs — uma tarefa da lista
public class Tarefa
{
    public int Id { get; }
    public string Titulo { get; }
    public bool Feita { get; private set; }

    public Tarefa(int id, string titulo)
    {
        if (string.IsNullOrWhiteSpace(titulo))
        {
            throw new ArgumentException("A tarefa precisa de um título.", nameof(titulo));
        }
        Id = id;
        Titulo = titulo.Trim();
    }

    public void Concluir()
    {
        Feita = true;
    }

    public override string ToString() => $"[{(Feita ? "x" : " ")}] {Id}. {Titulo}";
}
LinhaO que faz
public class TarefaDeclara a classe. public: qualquer parte do programa pode usá-la.
public int Id { get; }Uma propriedade só de leitura: o número da tarefa. Só o construtor pode dar valor a ela; depois, ninguém muda (aula Propriedades).
public string Titulo { get; }O texto da tarefa, também só de leitura.
public bool Feita { get; private set; }Todo mundo pode ler se está feita, mas só a própria classe pode mudar (o set é private). Começa com false, o valor padrão do bool.
public Tarefa(int id, string titulo)O construtor: roda no new Tarefa(…) e preenche o papel.
if (string.IsNullOrWhiteSpace(titulo))Recusa título vazio ou só com espaços. Uma tarefa sem texto não serve para nada, e é melhor recusar na porta do que descobrir depois.
throw new ArgumentException("…", nameof(titulo));Lança uma exceção: "argumento inválido". O nameof(titulo) vira o texto "titulo", o nome do parâmetro culpado (aula throw).
Titulo = titulo.Trim();Guarda o título sem os espaços do começo e do fim.
public void Concluir()O único jeito de marcar como feita. Quem está fora da classe pede "conclua", em vez de mexer no Feita direto.
public override string ToString() => …Diz como a tarefa vira texto. É ele que o Console.WriteLine(t) usa. Sem ele, sairia só o nome da classe, Tarefa (aula A Classe object).
$"[{(Feita ? "x" : " ")}] {Id}. {Titulo}"Monta [x] 2. Estudar C# ou [ ] 1. Comprar pão. O ternário fica entre parênteses porque, dentro de { }, o : sozinho seria lido como início de um formato.

CS0272: o set é privado

A Ana tentou marcar a tarefa como feita "na mão", pelo Program.cs:

List<Tarefa> tarefas = [];
tarefas.Add(new Tarefa(1, "Comprar pão"));
tarefas[0].Feita = true;
Console.WriteLine(tarefas[0]);

$ dotnet run
/home/ana/projetos/Tarefas/Program.cs(3,1): error CS0272: A propriedade ou o indexador "Tarefa.Feita" não pode ser usado neste contexto porque o acessador set é inacessível [/home/ana/projetos/Tarefas/Tarefas.csproj]

O que significa: o Feita tem private set; fora da classe, ele pode ser lido, mas não mudado. Em inglês: The property or indexer 'Tarefa.Feita' cannot be used in this context because the set accessor is inaccessible.

Como consertar: peça para a tarefa se concluir: tarefas[0].Concluir();. Esse é o motivo de existir o private set: se amanhã concluir uma tarefa também tiver de guardar a data, a mudança é feita num lugar só, o Concluir.

Versão 2 · A classe ListaDeTarefas e o menu

Na versão 1, o Program.cs mexia direto na List: escolhia o número de cada tarefa, contava as pendentes. Com o menu, essas regras iriam se espalhar pelo programa. A solução é uma segunda classe, que guarda a lista e é a única que mexe nela. Pense numa secretária que cuida do quadro de avisos: a Ana diz "anota isso" ou "risca a 2", e a secretária escolhe o número e cola o papel.

// ListaDeTarefas.cs — guarda as tarefas e dá os números
public class ListaDeTarefas
{
    private readonly List<Tarefa> _tarefas = [];
    private int _proximoId = 1;

    public int Total => _tarefas.Count;
    public int Pendentes => _tarefas.Count(t => !t.Feita);

    public Tarefa Adicionar(string titulo)
    {
        Tarefa nova = new(_proximoId, titulo);
        _tarefas.Add(nova);
        _proximoId++;
        return nova;
    }

    public Tarefa? Buscar(int id) => _tarefas.Find(t => t.Id == id);

    public void Mostrar()
    {
        if (Total == 0)
        {
            Console.WriteLine("Nenhuma tarefa. Aproveite o dia!");
            return;
        }
        foreach (Tarefa t in _tarefas)
        {
            Console.WriteLine(t);
        }
        Console.WriteLine($"{Pendentes} de {Total} por fazer.");
    }
}
LinhaO que faz
private readonly List<Tarefa> _tarefas = [];A lista de verdade, escondida (private). O readonly impede trocar a lista inteira por outra; mexer no conteúdo (Add, Remove) continua valendo. O _ no começo é a convenção do C# para campos privados (aula Campos).
private int _proximoId = 1;O número que a próxima tarefa vai receber. Só a lista sabe; a Ana não precisa escolher.
public int Total => _tarefas.Count;Uma propriedade calculada: a cada leitura, conta de novo. Não tem set.
public int Pendentes => _tarefas.Count(t => !t.Feita);Quantas não estão feitas. O Count(…) com uma condição é do LINQ; o ! é o "não".
public Tarefa Adicionar(string titulo)Cria a tarefa com o próximo número, guarda e devolve a tarefa nova, para quem chamou poder mostrá-la.
Tarefa nova = new(_proximoId, titulo);O new(…) sem o nome da classe funciona porque o tipo já está escrito à esquerda C# 9.
public Tarefa? Buscar(int id) => _tarefas.Find(t => t.Id == id);Find é da própria List: devolve a primeira tarefa com aquele número, ou null se não houver. O Tarefa? avisa quem chama que pode vir null (aula Referências Anuláveis).
public void Mostrar()Mostra a lista, ou um aviso quando está vazia.

O Program.cs agora só conversa com a Ana. Toda regra fica na lista:

// Program.cs — versão 2: o menu
ListaDeTarefas lista = new();

Console.WriteLine("=== Lista de Tarefas ===");
while (true)
{
    Console.WriteLine();
    Console.WriteLine("1) Listar  2) Adicionar  3) Concluir  0) Sair");
    Console.Write("Opção: ");
    string? opcao = Console.ReadLine();
    if (opcao is null || opcao == "0")
    {
        break;
    }
    switch (opcao)
    {
        case "1":
            lista.Mostrar();
            break;
        case "2":
            Console.Write("Título: ");
            string titulo = Console.ReadLine() ?? "";
            if (string.IsNullOrWhiteSpace(titulo))
            {
                Console.WriteLine("O título não pode ficar vazio.");
                break;
            }
            Tarefa nova = lista.Adicionar(titulo);
            Console.WriteLine($"Anotado: {nova}");
            break;
        case "3":
            Console.Write("Número da tarefa: ");
            if (!int.TryParse(Console.ReadLine(), out int id))
            {
                Console.WriteLine("Digite o número que aparece na lista.");
                break;
            }
            Tarefa? t = lista.Buscar(id);
            if (t is null)
            {
                Console.WriteLine($"Não há tarefa {id}.");
            }
            else if (t.Feita)
            {
                Console.WriteLine($"A tarefa {id} já estava feita.");
            }
            else
            {
                t.Concluir();
                Console.WriteLine($"Feito: {t}");
            }
            break;
        default:
            Console.WriteLine("Opção inválida.");
            break;
    }
}
Console.WriteLine($"Até logo! Por fazer: {lista.Pendentes}.");

CS0122: o campo é privado

Para apagar tudo de uma vez, a Ana tentou usar a List que está dentro da ListaDeTarefas:

ListaDeTarefas lista = new();
lista.Adicionar("Comprar pão");
lista._tarefas.Clear();
lista.Mostrar();

$ dotnet run
/home/ana/projetos/Tarefas/Program.cs(3,7): error CS0122: "ListaDeTarefas._tarefas" é inacessível devido ao seu nível de proteção [/home/ana/projetos/Tarefas/Tarefas.csproj]

Ocorreu uma falha no build. Corrija os erros de build e execute novamente.

O que significa: o _tarefas é private: só o código dentro da classe ListaDeTarefas o enxerga. Em inglês: 'ListaDeTarefas._tarefas' is inaccessible due to its protection level. Aula: public, private e internal.

// ListaDeTarefas.cs — guarda as tarefas, num arquivo também
public class ListaDeTarefas
{
    private readonly List<Tarefa> _tarefas = [];
    private int _proximoId = 1;
    private readonly string _arquivo;

    public ListaDeTarefas(string arquivo)
    {
        _arquivo = arquivo;
        Carregar();
    }

    public int Total => _tarefas.Count;
    public int Pendentes => _tarefas.Count(t => !t.Feita);

    public Tarefa Adicionar(string titulo)
    {
        Tarefa nova = new(_proximoId, titulo);
        _tarefas.Add(nova);
        _proximoId++;
        return nova;
    }

    public Tarefa? Buscar(int id) => _tarefas.Find(t => t.Id == id);

    // Devolve true se achou e apagou a tarefa com esse número.
    public bool Remover(int id) => _tarefas.RemoveAll(t => t.Id == id) > 0;

    // Apaga todas as feitas e devolve quantas apagou.
    public int LimparFeitas() => _tarefas.RemoveAll(t => t.Feita);

    public void Mostrar()
    {
        if (Total == 0)
        {
            Console.WriteLine("Nenhuma tarefa. Aproveite o dia!");
            return;
        }
        foreach (Tarefa t in _tarefas)
        {
            Console.WriteLine(t);
        }
        Console.WriteLine($"{Pendentes} de {Total} por fazer.");
    }

    // Uma linha por tarefa: número|feita (1 ou 0)|título
    public void Salvar()
    {
        using StreamWriter escritor = new(_arquivo);
        foreach (Tarefa t in _tarefas)
        {
            escritor.WriteLine($"{t.Id}|{(t.Feita ? 1 : 0)}|{t.Titulo}");
        }
    }

    private void Carregar()
    {
        if (!File.Exists(_arquivo))
        {
            return;                     // primeira vez: lista vazia
        }
        foreach (string linha in File.ReadAllLines(_arquivo))
        {
            string[] partes = linha.Split('|', 3);
            if (partes.Length != 3 || !int.TryParse(partes[0], out int id))
            {
                continue;               // linha estragada: pula
            }
            _tarefas.Add(new Tarefa(id, partes[2], partes[1] == "1"));
        }
        if (_tarefas.Count > 0)
        {
            _proximoId = _tarefas.Max(t => t.Id) + 1;
        }
    }
}

Sem o using, o arquivo fica vazio

Numa das tentativas, a Ana escreveu o Salvar sem o using (só StreamWriter escritor = new(_arquivo);). O programa compilou, rodou e disse que salvou. Este Program.cs de teste anota duas tarefas e salva:

Salvei 2 tarefas.
$ ls -l tarefas.txt
-rw-rw-r-- 1 ana ana 0 out 17 12:59 tarefas.txt
$ cat tarefas.txt

O que aconteceu: o arquivo tem 0 bytes. O StreamWriter não escreve no disco a cada WriteLine: ele junta o texto num "balde" na memória e esvazia o balde de uma vez, quando enche ou quando é fechado. Sem o using, ninguém fechou o arquivo; o programa terminou com o balde cheio, e o texto foi embora com ele. Não houve erro nem aviso.

Como consertar: todo StreamWriter (e todo objeto que abre um arquivo) vai com using. Com o using de volta, o mesmo teste grava as duas linhas (32 bytes):

$ dotnet run
Salvei 2 tarefas.
$ cat tarefas.txt
1|0|Comprar pão
2|0|Estudar C#

// ListaDeTarefas.cs — guarda as tarefas, num arquivo também
public class ListaDeTarefas
{
    private readonly List<Tarefa> _tarefas = [];
    private int _proximoId = 1;
    private readonly string _arquivo;

    public ListaDeTarefas(string arquivo)
    {
        _arquivo = arquivo;
        Carregar();
    }

    public int Total => _tarefas.Count;
    public int Pendentes => _tarefas.Count(t => !t.Feita);

    public Tarefa Adicionar(string titulo)
    {
        Tarefa nova = new(_proximoId, titulo);
        _tarefas.Add(nova);
        _proximoId++;
        return nova;
    }

    public Tarefa? Buscar(int id) => _tarefas.Find(t => t.Id == id);

    // Devolve true se achou e apagou a tarefa com esse número.
    public bool Remover(int id) => _tarefas.RemoveAll(t => t.Id == id) > 0;

    // Apaga todas as feitas e devolve quantas apagou.
    public int LimparFeitas() => _tarefas.RemoveAll(t => t.Feita);

    public void Mostrar()
    {
        if (Total == 0)
        {
            Console.WriteLine("Nenhuma tarefa. Aproveite o dia!");
            return;
        }
        foreach (Tarefa t in _tarefas)
        {
            Console.WriteLine(t);
        }
        Console.WriteLine($"{Pendentes} de {Total} por fazer.");
    }

    // Uma linha por tarefa: número|feita (1 ou 0)|título
    public void Salvar()
    {
        StreamWriter escritor = new(_arquivo);
        foreach (Tarefa t in _tarefas)
        {
            escritor.WriteLine($"{t.Id}|{(t.Feita ? 1 : 0)}|{t.Titulo}");
        }
    }

    private void Carregar()
    {
        if (!File.Exists(_arquivo))
        {
            return;                     // primeira vez: lista vazia
        }
        foreach (string linha in File.ReadAllLines(_arquivo))
        {
            string[] partes = linha.Split('|', 3);
            if (partes.Length != 3 || !int.TryParse(partes[0], out int id))
            {
                continue;               // linha estragada: pula
            }
            _tarefas.Add(new Tarefa(id, partes[2], partes[1] == "1"));
        }
        if (_tarefas.Count > 0)
        {
            _proximoId = _tarefas.Max(t => t.Id) + 1;
        }
    }
}

// Tarefa.cs — uma tarefa da lista
public class Tarefa
{
    public int Id { get; }
    public string Titulo { get; }
    public bool Feita { get; private set; }

    public Tarefa(int id, string titulo, bool feita = false)
    {
        if (string.IsNullOrWhiteSpace(titulo))
        {
            throw new ArgumentException("A tarefa precisa de um título.", nameof(titulo));
        }
        Id = id;
        Titulo = titulo.Trim();
        Feita = feita;
    }

    public void Concluir()
    {
        Feita = true;
    }

    public override string ToString() => $"[{(Feita ? "x" : " ")}] {Id}. {Titulo}";
}

Formas diferentes

Em vez de…Daria para…Qual usar
class Tarefa com private setrecord Tarefa(int Id, string Titulo, bool Feita) e with { Feita = true }O record é ótimo para dados que só se leem (o projeto Estoque usa). Aqui a tarefa tem regra (o título não pode ser vazio) e uma ação (Concluir): a classe deixa isso mais claro.
Uma ListaDeTarefas que esconde a ListUma List<Tarefa> solta no Program.csFunciona para programas pequenos (a versão 1 fez assim). Quando as regras crescem (números, salvar a cada mudança), uma classe que guarda a lista evita repetir código e erros como o do RemoveAt.
tarefas.txt com |tarefas.json com JsonSerializerO JSON lida sozinho com textos que têm |, quebras de linha e aspas (aula JSON; o projeto Agenda usa). O texto com | se lê e se conserta à mão, num editor.
using StreamWriter escritor = new(…);File.WriteAllLines(_arquivo, linhas)Também fecha o arquivo sozinho e é mais curto. O StreamWriter foi usado para mostrar o using, que você vai precisar com qualquer arquivo aberto aos poucos.
As classes sem namespacenamespace Tarefas; no topo de cada arquivoNum projeto maior, use o namespace (aula Namespaces e using). Num projeto de três arquivos, ele não muda nada.

Desafios extras

  • Editar: uma opção que troca o título de uma tarefa. Como o Titulo só tem get, crie na Tarefa um método Renomear(string novo) que valida como o construtor (troque o { get; } por { get; private set; }).
  • Data de conclusão: uma propriedade DateTime? FeitaEm, preenchida no Concluir (aula Datas e Horas). Grave no arquivo como um quarto campo… e pense em onde ele deve ficar, por causa do Split('|', 3).
  • Desfazer: uma opção que volta uma tarefa feita para pendente.
  • Ordem: listar primeiro as pendentes, depois as feitas, com OrderBy(t => t.Feita) (o false vem antes do true).

Resumo

  • Cada classe no seu arquivo; o projeto compila todos os .cs da pasta juntos.
  • { get; } só de leitura, { get; private set; } lida por todos e mudada só pela classe. Ações viram métodos (Concluir).
  • O construtor valida e recusa dados ruins com throw new ArgumentException(…); quem chama confere antes.
  • override ToString() decide como o objeto aparece no Console.WriteLine.
  • Uma classe que guarda a List como private concentra as regras; quem está fora pede por métodos.
  • O número de uma tarefa é uma etiqueta, não a posição: procure com Find e apague com RemoveAll.
  • Arquivo: confira File.Exists, leia com File.ReadAllLines, grave com StreamWriter sempre com using.
