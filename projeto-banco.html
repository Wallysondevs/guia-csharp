Projeto Conta Bancária (classes)

Uma conta bancária é o exemplo clássico de orientação a objetos, e por um bom motivo: ela tem dados (o titular, o saldo) e regras (não dá para sacar mais do que tem, não dá para depositar um valor negativo). Neste projeto, a Ana constrói as contas da lojinha em quatro passos: primeiro uma classe ingênua, que deixa o saldo ficar negativo; depois uma classe que protege as próprias regras; depois o extrato e a transferência; e, no fim, uma conta poupança que herda tudo da conta comum.

Você vai praticar
  • Criar uma classe com campos, métodos e objetos com new.
  • Encapsular: propriedades com private set e um construtor.
  • Recusar operações inválidas com throw e tratar com try e catch.
  • Guardar o extrato numa List de records e usar parâmetros opcionais.
  • Herdar com herança, chamar o construtor da classe-mãe com base e sobrescrever com virtual e override.
  • Dinheiro sempre em decimal, mostrado com :C.

O que vamos construir

No fim, a Ana tem uma conta corrente e uma poupança. Ela deposita R$ 1.500 na corrente, passa R$ 1.000 para a poupança, e a poupança rende 0,5% no mês:

Versão 1 · Uma classe Conta

Uma classe é a "planta" de um tipo de objeto: diz que dados ele guarda e o que ele sabe fazer. A conta guarda o titular e o saldo, e sabe depositar e sacar.

class Conta
{
    public string Titular = "";
    public decimal Saldo;

    public void Depositar(decimal valor)
    {
        Saldo += valor;
    }

    public void Sacar(decimal valor)
    {
        Saldo -= valor;
    }
}

Conta conta = new Conta();
conta.Titular = "Ana";
conta.Depositar(100m);
conta.Sacar(30m);
Console.WriteLine($"{conta.Titular}: {conta.Saldo:C}");

conta.Sacar(500m);
Console.WriteLine($"{conta.Titular}: {conta.Saldo:C}");

conta.Saldo = 1_000_000m;
Console.WriteLine($"{conta.Titular}: {conta.Saldo:C}");

Dinheiro sempre em decimal. Um campo numérico começa em 0.

O new cria um objeto a partir da planta: uma conta de verdade, com o seu próprio saldo.

Chama o método naquele objeto. O m faz do 100 um decimal.

A primeira linha está certa: 100 − 30 = 70. As outras duas mostram o problema desta versão. A conta aceitou um saque de R$ 500 com R$ 70 de saldo e ficou negativa. E, pior, a última linha do Program.cs mudou o saldo direto, para um milhão, sem depósito nenhum. A classe tem os dados, mas não tem como proteger as regras: qualquer um mexe em qualquer coisa. Versão 2 · Encapsular: a conta protege o saldo

A ideia do encapsulamento é a do caixa do banco: você não abre o cofre, você pede ao caixa, e ele confere se pode. Três mudanças:

  • O saldo vira uma propriedade que todos podem ler, mas só a própria classe pode mudar (private set).
  • Um construtor obriga a dizer o titular na hora de criar a conta.
  • Depositar e Sacar conferem o valor e, se ele for inválido, lançam uma exceção (throw) em vez de fazer a conta errada.
class Conta
{
    public string Titular { get; }
    public decimal Saldo { get; private set; }

    public Conta(string titular)
    {
        if (string.IsNullOrWhiteSpace(titular))
        {
            throw new ArgumentException("O titular não pode ficar vazio.");
        }
        Titular = titular;
    }

    public void Depositar(decimal valor)
    {
        if (valor <= 0)
        {
            throw new ArgumentException("O depósito tem de ser maior que zero.");
        }
        Saldo += valor;
    }

    public void Sacar(decimal valor)
    {
        if (valor <= 0)
        {
            throw new ArgumentException("O saque tem de ser maior que zero.");
        }
        if (valor > Saldo)
        {
            throw new InvalidOperationException($"Saldo insuficiente: o saldo é {Saldo:C} e o saque, {valor:C}.");
        }
        Saldo -= valor;
    }
}

Conta conta = new Conta("Ana");
conta.Depositar(100m);
conta.Sacar(30m);
Console.WriteLine($"{conta.Titular}: {conta.Saldo:C}");

}
catch (InvalidOperationException erro)
{
    Console.WriteLine($"Não deu: {erro.Message}");

try

}
catch (ArgumentException erro)
{

}

Console.WriteLine($"{conta.Titular}: {conta.Saldo:C}");
public string Titular { get; }
Uma propriedade só de leitura: recebe valor no construtor e nunca mais muda.
public decimal Saldo { get; private set; }
Todo mundo lê (get público); só o código dentro da classe muda (private set). Assim, o único jeito de mexer no saldo é por Depositar e Sacar, que conferem as regras.
public Conta(string titular)
O construtor: roda no new. Agora new Conta() sem titular nem compila; é preciso new Conta("Ana").
string.IsNullOrWhiteSpace(titular)
"É nulo, vazio ou só espaços?". Um titular assim é recusado.
throw new ArgumentException("…");
Lança uma exceção: a operação para ali, nada muda, e quem chamou fica sabendo. ArgumentException quer dizer "o argumento que você passou é inválido".
throw new InvalidOperationException(…)
"A operação não pode ser feita agora": o valor é bom, mas o saldo não dá.
catch (InvalidOperationException erro)
No Program.cs, quem usa a conta decide o que fazer com a recusa. erro.Message é o texto que a conta escreveu no throw.

Não deu: O depósito tem de ser maior que zero.

O saque grande e o depósito negativo foram recusados, e o saldo continuou em R$ 70,00.

/home/ana/projetos/Banco/Program.cs(3,1): error CS0272: A propriedade ou o indexador "Conta.Saldo" não pode ser usado neste contexto porque o acessador set é inacessível [/home/ana/projetos/Banco/Banco.csproj]

O que significa: o set do Saldo é private, então, fora da classe Conta, ninguém pode atribuir um valor a ele (em inglês, the set accessor is inaccessible). É exatamente o que queríamos: o erro aparece na compilação, antes de o programa rodar.

Como consertar: não é para consertar a classe, é para usar a porta certa: conta.Depositar(…).

Versão 3 · Extrato e transferência

Um banco não guarda só o saldo: guarda cada movimentação, para o extrato. Cada uma tem uma descrição e um valor (positivo para entradas, negativo para saídas). É um dado simples, que não muda depois de criado: um record, no seu próprio arquivo.

record Movimentacao(string Descricao, decimal Valor);

A Conta ganha a lista de movimentações, uma descrição opcional em Depositar e Sacar, e dois métodos novos: Transferir e MostrarExtrato.

class Conta
{
    private readonly List<Movimentacao> _movimentacoes = new();

    public string Titular { get; }
    public decimal Saldo { get; private set; }

    public Conta(string titular)
    {
        if (string.IsNullOrWhiteSpace(titular))
        {
            throw new ArgumentException("O titular não pode ficar vazio.");
        }
        Titular = titular;
    }

    public void Depositar(decimal valor, string descricao = "Depósito")
    {
        if (valor <= 0)
        {
            throw new ArgumentException("O depósito tem de ser maior que zero.");
        }
        Saldo += valor;
        _movimentacoes.Add(new Movimentacao(descricao, valor));
    }

    public void Sacar(decimal valor, string descricao = "Saque")
    {
        if (valor <= 0)
        {
            throw new ArgumentException("O saque tem de ser maior que zero.");
        }
        if (valor > Saldo)
        {
            throw new InvalidOperationException($"Saldo insuficiente: o saldo é {Saldo:C} e o saque, {valor:C}.");
        }
        Saldo -= valor;
        _movimentacoes.Add(new Movimentacao(descricao, -valor));
    }

    public void Transferir(Conta destino, decimal valor)
    {
        Sacar(valor, $"Transferência para {destino.Titular}");
        destino.Depositar(valor, $"Transferência de {Titular}");
    }

    public void MostrarExtrato()
    {
        Console.WriteLine($"Extrato de {Titular}");
        foreach (Movimentacao m in _movimentacoes)
        {
            Console.WriteLine($"  {m.Descricao,-26} {m.Valor,12:C}");
        }
        Console.WriteLine($"  {"Saldo",-26} {Saldo,12:C}");
    }
}

bruno.Depositar(80m, "Venda do caderno");

Um parâmetro opcional: quem não passar descrição ganha "Depósito". ana.Depositar(1500m) continua funcionando.
new Movimentacao(descricao, -valor)
No saque, o valor entra negativo: o extrato mostra -R$ 200,00.

Recebe outra conta como parâmetro. Primeiro saca desta (se o saldo não der, o Sacar lança a exceção e o depósito nem acontece), depois deposita na outra.

Por que Transferir usa Sacar e Depositar?

Daria para escrever Saldo -= valor; destino.Saldo += valor; (dentro da classe, o private set deixa, até na outra conta). Mas aí a transferência pularia as regras: aceitaria valor negativo e saldo insuficiente, e não apareceria no extrato. Reaproveitando os métodos, toda regra fica num lugar só.

Versão 4 · A poupança herda da conta

A Ana quer uma poupança para a reserva da loja. Uma poupança é uma conta (tem titular, saldo, depósito, saque, extrato) com uma coisa a mais: ela rende juros. Copiar a classe Conta inteira seria duplicar tudo. Com herança, a ContaPoupanca herda tudo da Conta e só acrescenta o que é dela.

Na Conta, uma linha nova: uma propriedade que diz o tipo da conta, marcada como virtual (as filhas podem trocá-la):

    public virtual string Tipo => "Conta corrente";

class ContaPoupanca : Conta
{
    public decimal TaxaMensal { get; }
    public override string Tipo => "Poupança";

    public ContaPoupanca(string titular, decimal taxaMensal) : base(titular)
    {
        TaxaMensal = taxaMensal;
    }

    public void RenderJuros()
    {
        decimal juros = Math.Round(Saldo * TaxaMensal, 2);
        if (juros > 0)
        {
            Depositar(juros, $"Rendimento de {TaxaMensal:P1}");
        }
    }
}

Conta corrente = new Conta("Ana");
ContaPoupanca reserva = new ContaPoupanca("Ana", 0.005m);

corrente.Depositar(1500m);
corrente.Transferir(reserva, 1000m);
reserva.RenderJuros();

List<Conta> contas = [corrente, reserva];
foreach (Conta conta in contas)
{
    Console.WriteLine($"{conta.Tipo,-15} {conta.Titular,-6} {conta.Saldo,12:C}");
}

Console.WriteLine();
reserva.MostrarExtrato();
class ContaPoupanca : Conta
O : diz "é uma Conta": a poupança herda Titular, Saldo, Depositar, Sacar, Transferir e MostrarExtrato.
public virtual string Tipo => "Conta corrente";
Na Conta: uma propriedade calculada (o => devolve o valor), que as classes filhas podem substituir.
public override string Tipo => "Poupança";
Na poupança: substitui (override) a versão da mãe.
: base(titular)
O construtor da poupança chama primeiro o construtor da Conta, que confere e guarda o titular (base). Depois guarda a taxa.
Math.Round(Saldo * TaxaMensal, 2)
Os juros, arredondados para centavos. Saldo é a propriedade herdada: a poupança pode ler, e muda só por Depositar.

Formato de porcentagem com 1 casa: 0.005m vira 0,5%.

Uma lista de Conta aceita a poupança, porque toda poupança é uma conta.

class Conta
{
    private readonly List<Movimentacao> _movimentacoes = new();

    public string Titular { get; }
    public decimal Saldo { get; private set; }
    public virtual string Tipo => "Conta corrente";

    public Conta(string titular)
    {
        if (string.IsNullOrWhiteSpace(titular))
        {
            throw new ArgumentException("O titular não pode ficar vazio.");
        }
        Titular = titular;
    }

    public void Depositar(decimal valor, string descricao = "Depósito")
    {
        if (valor <= 0)
        {
            throw new ArgumentException("O depósito tem de ser maior que zero.");
        }
        Saldo += valor;
        _movimentacoes.Add(new Movimentacao(descricao, valor));
    }

    public void Sacar(decimal valor, string descricao = "Saque")
    {
        if (valor <= 0)
        {
            throw new ArgumentException("O saque tem de ser maior que zero.");
        }
        if (valor > Saldo)
        {
            throw new InvalidOperationException($"Saldo insuficiente: o saldo é {Saldo:C} e o saque, {valor:C}.");
        }
        Saldo -= valor;
        _movimentacoes.Add(new Movimentacao(descricao, -valor));
    }

    public void Transferir(Conta destino, decimal valor)
    {
        Sacar(valor, $"Transferência para {destino.Titular}");
        destino.Depositar(valor, $"Transferência de {Titular}");
    }

    public void MostrarExtrato()
    {
        Console.WriteLine($"Extrato de {Titular}");
        foreach (Movimentacao m in _movimentacoes)
        {
            Console.WriteLine($"  {m.Descricao,-26} {m.Valor,12:C}");
        }
        Console.WriteLine($"  {"Saldo",-26} {Saldo,12:C}");
    }
}

record Movimentacao(string Descricao, decimal Valor);

O que o projeto juntou: classes e objetos, propriedades com private set, construtores, throw e try/catch, um record numa List private readonly, parâmetros opcionais, herança com base, virtual e override e decimal com :C e :P1.

Desafios extras

  1. Exceção própria. Troque a InvalidOperationException por uma SaldoInsuficienteException com as propriedades Saldo e Valor (veja Exceções Próprias).
  2. Cheque especial. Crie uma ContaCorrente com um Limite, que deixa o saldo ficar negativo até o limite. Para isso, o Sacar da Conta precisa ser virtual, ou a regra "quanto pode sacar" pode virar uma propriedade virtual decimal Disponivel.
  3. Extrato só de leitura. Exponha as movimentações com public IReadOnlyList<Movimentacao> Movimentacoes => _movimentacoes; e mova o MostrarExtrato para o Program.cs: a conta guarda os dados, e quem mostra é o programa.
  4. Testes. Num projeto de testes, confira que um saque maior que o saldo lança a exceção e não muda o saldo (veja Testes (xUnit)).
  5. Salvar as contas. Guarde as contas num arquivo JSON, como na Agenda. Cuidado: com o private set, o JsonSerializer não consegue preencher o saldo sozinho (veja JSON).

Resumo

  • Uma classe junta dados e comportamento; cada new cria um objeto independente.
  • Campos públicos deixam qualquer um quebrar as regras. Com { get; private set; }, o saldo só muda pelos métodos da classe (fora dela, CS0272).
  • O construtor obriga a criar o objeto num estado válido; os métodos recusam operações inválidas com throw, e quem chama trata com try/catch.
  • Um record numa lista private readonly guarda o extrato; reaproveitar Sacar e Depositar na transferência mantém as regras num lugar só.
  • Com herança, a filha recebe tudo da mãe e chama o construtor dela com : base(…) (senão, CS7036).
  • Só membros virtual podem ser substituídos com override (senão, CS0506); numa lista da mãe, vale a versão do objeto de verdade.
