C# Soluções e Vários Projetos

Um programa de verdade raramente é um projeto só. A lojinha da Ana vai ter o programa de console, uma parte com as regras do estoque (que um dia também vai servir a um site), e os testes. Cada parte é um projeto, com o seu .csproj. Para juntar tudo e compilar de uma vez, o .NET usa uma solução: um arquivo que lista os projetos que andam juntos. Nesta aula você vai criar uma solução no formato novo do .NET 10, o .slnx, pôr dois projetos nela e fazer um usar o outro.

Você vai aprender
  • O que é uma solução e para que ela serve.
  • A criar uma com dotnet new sln e a ler o arquivo .slnx .NET 10.
  • A organizar os projetos na pasta src e a pô-los na solução com dotnet sln add, list e remove.
  • A compilar tudo com um dotnet build e a rodar um projeto com dotnet run --project.
  • A fazer um projeto usar o outro com dotnet reference add.
  • O formato antigo .sln, o dotnet sln migrate e os erros MSB1011 e MSB4006.

Todas as saídas desta aula são reais, feitas com o .NET 10 SDK (10.0.112) na máquina fictícia da Ana, na pasta ~/projetos/Loja. Você precisa já conhecer Projetos e O Arquivo .csproj.

A ideia: o fichário e os cadernos

Na escola, a Ana tinha um caderno para cada matéria e um fichário que juntava todos. O fichário não tem conteúdo próprio: ele só diz quais cadernos fazem parte do ano. Para levar o ano inteiro para casa, ela pega o fichário.

Na escolaNo .NETArquivo
Um cadernoUm projeto: um programa ou uma bibliotecaLoja.App.csproj
O fichárioA solução: a lista dos projetosLoja.slnx
Levar o fichário para casadotnet build na pasta da solução compila todos os projetos

Solução, em inglês, é solution, e por isso a extensão .sln (a antiga) e .slnx (a nova, com o x de XML). Editores como o Visual Studio e o Rider abrem a solução para mostrar todos os projetos de uma vez; o VS Code, com a extensão C# Dev Kit, também.

"Solução, acrescente": põe os projetos na solução da pasta atual. Pode ser a pasta do projeto (o dotnet acha o .csproj dentro dela) ou o caminho do próprio .csproj. Vários de uma vez, separados por espaço.
<Folder Name="/src/">
Uma "pasta da solução": um grupo que os editores mostram como uma pastinha. O dotnet sln add criou o grupo /src/ porque os projetos estão na pasta src.
<Project Path="…" />
Um projeto da solução: só o caminho do .csproj, a partir da pasta da solução. É tudo o que o .slnx precisa guardar.
dotnet sln list
Lista os projetos da solução.

Uma linha Projeto -> …dll para cada projeto. Cada um continua com a sua própria pasta bin. Repare que a biblioteca virou só um .dll (sem executável): ela não roda sozinha. O mesmo vale para dotnet test, dotnet clean e dotnet format: na pasta da solução, eles agem sobre todos os projetos.

Rodar: dotnet run --project

Já o dotnet run precisa saber qual programa rodar:

$ dotnet run
Não foi possível localizar um projeto para executar. Verifique se existe um projeto em /home/ana/projetos/Loja ou passe o caminho para o projeto usando --project.
$ dotnet run --project src/Loja.App
Hello, World!

Com --project, a Ana continua na pasta da solução. A outra forma é entrar na pasta do projeto (cd src/Loja.App) e rodar dotnet run lá.

5. Um projeto usar o outro: dotnet reference add

Agora o conteúdo. A Ana apaga o Class1.cs e escreve a classe Produto na biblioteca:

namespace Loja.Estoque;

public class Produto(string nome, decimal preco, int quantidade)
{
    public string Nome { get; } = nome;
    public decimal Preco { get; } = preco;
    public int Quantidade { get; } = quantidade;

    public decimal Total => Preco * Quantidade;
}

E o programa usa essa classe:

Converter: dotnet sln migrate

Para passar um .sln para o formato novo (aqui, uma Antiga.sln vazia, criada de novo com dotnet new sln --format sln -n Antiga):

$ dotnet sln Antiga.sln add src/Loja.App
O projeto ‘src/Loja.App/Loja.App.csproj’ foi adicionado à solução.
O projeto ‘src/Loja.Estoque/Loja.Estoque.csproj’ foi adicionado à solução.
$ dotnet sln Antiga.sln migrate
Arquivo .slnx /home/ana/projetos/Loja/Antiga.slnx gerado.
$ ls
Antiga.sln
Antiga.slnx
Loja.slnx
src
dotnet sln Antiga.sln add …
Com duas soluções na pasta, diga qual logo depois do sln. Repare: a Ana pediu só o Loja.App, e o Loja.Estoque veio junto. É que o Loja.App usa o Loja.Estoque (a referência da seção 5), e o dotnet sln add acrescenta também os projetos usados.
dotnet sln Antiga.sln migrate
"Migre": cria o Antiga.slnx ao lado. O .sln original não é apagado: confira o novo e apague o velho você mesmo.

A Ana apagou as duas (rm Antiga.sln Antiga.slnx), porque a lojinha já tem a Loja.slnx. Uma pasta deve ter uma solução só (veja "Quando dá errado").

7. Tirar um projeto: dotnet sln remove

$ dotnet sln remove src/Loja.Estoque
O projeto `src/Loja.Estoque/Loja.Estoque.csproj` foi removido da solução.
$ dotnet sln list
Projetos
--------
src/Loja.App/Loja.App.csproj

O remove só tira o projeto da lista: a pasta src/Loja.Estoque e os arquivos continuam no disco. A Ana pôs de volta com dotnet sln add src/Loja.Estoque.

Quando dá errado

error MSB1011: duas soluções na mesma pasta 
$ ls
Antiga.sln
Loja.slnx
src
$ dotnet build
MSBUILD : error MSB1011: Especifique o arquivo de solução ou de projeto a usar porque esta pasta contém mais de um arquivo de solução ou de projeto.

O que aconteceu: com duas soluções (ou uma solução e um .csproj) na pasta, o dotnet não sabe qual usar. Acontece muito logo depois de um migrate.

Como resolver: diga qual (dotnet build Loja.slnx) ou, melhor, deixe uma só. Nunca ponha a solução na mesma pasta de um .csproj: a solução fica em cima, os projetos em src/.

Não foi possível encontrar o projeto ou diretório e já contém o projeto 
$ dotnet sln add src/Loja.Relatorios
Não foi possível encontrar o projeto ou diretório ‘src/Loja.Relatorios’.
$ dotnet sln add src/Loja.App
A solução /home/ana/projetos/Loja/Loja.slnx já contém o projeto src/Loja.App/Loja.App.csproj.

O que aconteceu: no primeiro, o projeto ainda não existe (ou o caminho está errado). No segundo, nada de errado: o projeto já estava na solução e não foi duplicado.

Como resolver: crie o projeto antes (dotnet new … -o src/Loja.Relatorios) e confira o caminho com ls src.

error CS0246: está na solução, mas o outro projeto não enxerga

O que aconteceu: é o erro da seção 5: O nome do tipo ou do namespace "Loja" não pode ser encontrado. A solução junta os projetos para compilar, mas não faz um usar o outro.

Como resolver: dotnet reference add src/Loja.Estoque --project src/Loja.App, o using Loja.Estoque; no arquivo e a classe public na biblioteca.

error MSB4006: Há uma dependência circular 
$ dotnet reference add src/Loja.App --project src/Loja.Estoque
A referência ‘..\Loja.App\Loja.App.csproj’ foi adicionada ao projeto.
$ dotnet build 2>&1 | tail -5
/usr/lib/dotnet/sdk/10.0.112/NuGet.targets(1294,5): error MSB4006: Há uma dependência circular no elemento gráfico de dependência circular de destino envolvendo o destino "_GenerateRestoreProjectPathWalk". [/home/ana/projetos/Loja/src/Loja.Estoque/Loja.Estoque.csproj]
    0 Aviso(s)
    1 Erro(s)

Tempo Decorrido 00:00:00.95

O que aconteceu: o Loja.App já usava o Loja.Estoque, e a Ana fez o Loja.Estoque usar o Loja.App também. Agora cada um precisa do outro pronto para ser compilado: um círculo sem começo. A tradução está confusa, mas a palavra-chave é "circular" (em inglês, There is a circular dependency).

Como resolver: as referências só podem ir num sentido: o programa usa a biblioteca, nunca o contrário. Tire a referência errada passando o caminho do arquivo .csproj:

$ dotnet reference remove --project src/Loja.Estoque/Loja.Estoque.csproj src/Loja.App/Loja.App.csproj
Referência de projeto ‘../Loja.App/Loja.App.csproj’ removida.

Cuidado: com o caminho da pasta (dotnet reference remove src/Loja.App --project src/Loja.Estoque), o SDK 10.0.112 calcula o caminho errado e responde Não foi possível encontrar a referência de projeto ‘../../Loja.App/Loja.App.csproj’, sem remover nada. Se a biblioteca precisar de algo do programa, esse algo deve mudar para a biblioteca.

Resumo

  • Uma solução é o fichário: a lista dos projetos que andam juntos. Ela não tem código.
  • dotnet new sln cria um .slnx .NET 10: XML simples com <Project Path="…" />. O formato antigo é o .sln; dotnet sln migrate converte.
  • Estrutura comum: a solução em cima, os projetos em src/ e os testes em tests/.
  • dotnet sln add, list e remove mexem na lista.
  • Na pasta da solução, dotnet build compila tudo, na ordem certa; para rodar, dotnet run --project src/Loja.App.
  • Para um projeto usar outro: dotnet reference add A --project B, que escreve um <ProjectReference>. As referências vão num sentido só.
